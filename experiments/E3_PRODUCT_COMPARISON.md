# E3 产品执行对照

## 范围与验收

用户于2026年11月2日确认本轮完成现有 E3 全链路对照与验收，不扩展为尚未实现的通用跨结果缓存。实现对象是已有的服务端可信最短路证明；候选、估时、事件说明和核验按当前产品流程生成。

保留原 E1 主实验 300×3×3 口径。本专项独立计数，不改 `protocol_v1.json`、`protocol_v2.json` 或原始记录。当前六组校园 OD 已见，明确为开发固定子集；不把它们改称未见留出任务。

1. 两策略使用同一实际 API、任务、图、事件、天气及核验。完整重算只移除可选证明句柄，保守复用携带服务器签发的句柄。两者均实际执行，不由参照结果代替。
2. 本机专用 PostgreSQL 库验证 owner、proof、版本和生命周期；事件文件与时钟隔离。天气固定为空，无模型调用。
3. 校园六组 OD 覆盖不变、路内外封闭、开路、自然到期、撤销、未来与已过期事件、方式不适用、路内外缓行、混合、提示、方式/起终点/硬约束变化、联合变化、基础图成本下降、不可达及恢复。
4. 道路关联和静态方式过滤作为共同空间输入冻结。独立评分从冻结边集合重建当前事件作用，自行检查真实响应的边链、端点、准入、长度、最优性、ETA与结构化事件说明，不读取产品核验结论。
5. 仅监听旧路径的弱策略另做受控小图诊断；覆盖开路和路外成本下降形成更短路线的反例，以及策略权重变更。
6. 每条件每策略3次计时，按场景族配对汇总；另1次操作数探针，探针不进入时延统计。过程时延覆盖 API 请求处理、身份/证明读取、重算或复用、核验、说明、证明签发与响应序列化；阶段耗时包含子阶段，不相加。
7. 输出实际 Dijkstra 调用次数和另行测量的邻接展开节点数。完整记录成功、失败、未知、不可达及版本拒绝，不按结果筛除。
8. 隔离集成回归另覆盖证明缺失/伪造/过期/外来owner/修订变化/存储故障和旧结果提交，不混入校园试验的分母。
9. 固定案例清单、代码和数据哈希后开始每批运行；诊断后修改代码，保留原批次并另建批次。完整原始响应、评分、汇总、运行环境、命令与验收材料可追溯。

## 完成条件

每个固定案例均有两策略实际执行及独立评分；所有预期拒绝与不可达单列；复用路径的有效性/最优性不低于完整重算；出现差异先定位并修复根因，不以修改评分掩盖。开销如实报告，允许维护策略在当前规模下没有收益。完成对应集成回归、来源核验、交接说明、提交与远端哈希验证后关闭本轮任务。
