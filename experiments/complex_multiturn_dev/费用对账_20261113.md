# 测试预算上界与平台账单的区别

用户提供的 DeepSeek 用量页面显示：11 月 13 日、全部 API Key 汇总消费为 4.31 元，共 853 次请求、16,286,975 tokens；页面注明数据可能延迟约 5 分钟。该数值是截图时的账户汇总，不单独等于本测试的费用，也不包含其他供应商的账单。

截至本轮继续前，本测试账本记录 478 次已结算模型请求，输入 9,128,621 tokens、输出 168,151 tokens；另有 89 次按上限计入的固定费用请求。账本的 19.869450 元是**预算控制上界，不是实际扣费**：

- 模型部分按全部输入缓存未命中、高峰价格估算：9,128,621 × 2 / 1,000,000 ＋ 168,151 × 8 / 1,000,000 ＝ 19.602450 元。
- 地图和网页等固定费用请求合计按 0.267 元上限计入，连同模型部分得到 19.869450 元。
- DeepSeek 官方定价将缓存命中和未命中分开，并区分高峰与闲时；网页 Search/Fetch 按成功请求计费。高德费用属于另一供应商。具体以 [DeepSeek 定价](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)及各供应商账单为准。

此前账本只保存了输入和输出 token 数，没有保存每次请求的缓存命中、未命中和分时数据，无法从该账本准确还原实际扣费。截图的账户范围和账本的测试范围不同，也不能将两者简单相减。原账本保留，不将保守上界伪装成实际费用。

本次用户授权在原 20 元上界基础上追加 20 元，即**同一账本累计保守上限 40 元**；没有清空或覆盖原始账本。每次付费调用前仍按所有输入均未命中缓存的峰值价格预留。对后来 API 明确返回的缓存命中、未命中和输出量，如果数值完整且与原先结算金额一致，读取账本时改按峰值缓存命中价、峰值未命中价和峰值输出价计算上界；其他情况仍按原来的全部未命中上界计入。峰值单价分别为每百万 token 0.04 元、2 元和 8 元，网页与地图等固定费用仍按各自上限计入。

例如，账本原始记录计算到 28.407860 元上界时，其中较早 19.869450 元因缺少缓存明细继续保守计入；使用后来已返回的缓存明细重新读取后的累计上界为 21.15466832 元。这个数字依然不是实际账单；账号级真实消费以供应商页面和账单为准。

2026-11-13 后续一次调用返回 HTTP 400，没有返回用量，守卫保留 0.18553 元预留并暂停。用户同意将该笔按预留上限计入并继续；账本追加记录，标记 `usage=unknown`，没有将该金额写成实际费用。处理后累计保守上界为 29.38470592 元，仍与供应商最终账单不同。

2026-11-14 最终核心题与变体题调用完成后，账本累计保守上界为 35.94558120 元，包含上述未知用量请求的 0.18553 元上界；该数字不是平台实际扣费。后续实际账户消费应以对应供应商账单为准。
