# LLM 主导对话与检索改造

日期：2026-11-06。状态：本轮代码已推送并部署，候选版本 `c485d61`；等待用户使用已安装的 App 做真实手机验收。用户已授权修改、整理工作区、推送和部署。论文与大批量实验继续暂停，Android 原生壳不在本轮改动范围。

## 目标与依据

用户提出：让模型理解完整自然语言、主动寻找符合条件的地点并解释，再由地图工具完成位置核对与时空计算。当前发布基线 `06e2b17` 的推荐在 `agents/planner.py` 的模型调用之前返回，`turns=0`；“独立火锅店、不要食堂档口、人均50元以内”被规则拦截为类别追问。常规推荐不携带菜系关键词到高德；已有模型工具表没有网页搜索，路线生成又提前终止解释。这些是本轮需要改变的行为。

## 实施安排

1. **对话主流程**：自然语言默认进入模型。原始需求、近期对话、当前任务、用户提供的出发点、搜索区域、已接受路线分别传递；由模型判断新任务、补充、修订和选择。增加可持久化的语义需求，显式保留否定、预算、数量及多段安排。地图按钮等结构化操作复用既有可靠路径。原规则流程仅保留为显式配置的回退版本，不在模型正常运行时抢答。
2. **检索与事实**：复用高德服务器端查询并支持关键词与区域检索，不必先知道出发点才能介绍地点。补充 DeepSeek Search/Fetch 的有界检索，来源、日期和未知字段可见。模型可寻找目录外候选，但名称、分店、坐标由实际查询核对；用户已纠正不存在的门店仍统一隔离。外部文本只作为资料，不得作为系统指令。在线结果不批量沉淀为公开静态库。
3. **统一交付**：模型在检索结果中筛选、排序、比较并组织说明；最终推荐通过服务器接受的地点 ID 对齐卡片与地图。推荐数量、非重复换批、候选续接、起点与区域区别、刷新恢复、迟到响应失效仍成立。路线工具后继续模型解释；距离、时间、限制与已接受空间结果一致，缺失事实不补写。
4. **保护已有能力**：保留修订/租约/取消隔离、来源隔离、坐标转换、有向边核验、道路有效期、维护依赖和完整重算回退。路线、天气、影像复核、管理台和地图操作回归；新语义状态的旧记录兼容与回退路径需单独检查。
5. **整合与发布**：逐个登记工作区的 HEAD、分支、未提交内容及独有成果；确认产品唯一基线，保留研究与历史证据，安全同步主工作区及维护中的整合区。过期交接与事实索引更新。发布前验证两处远端、可回退版本和线上当前状态，发布后检查真实模型、检索、地图及服务。真实手机单列，未实测不计通过。

## 主要接口与边界

- 默认采用现有模型接口和工具执行器，增加模型主导模式与明确的旧版回退开关，不引入新的前端框架或模型 SDK。
- 语义状态在现有任务 JSON 合约内兼容扩展；业务数据库、会话归属和原始实验档案不替换。模型只能提议修订，最终提交仍受服务器任务版本检查。
- 搜索证据与地点身份分开记录：网页证明其所声称的内容与时间，高德提供门店记录与位置，二者不能自动证明实时营业或现场通行。
- 模型/搜索超时、失败、空结果与信息冲突分别报告；已知结果保留可恢复。不给旧规则的静默回答伪装成模型成功。
- DeepSeek 搜索接口参考：https://api-docs.deepseek.com/guides/search/ 。小规模联调测量实耗；不运行54次开发批次或正式付费实验。
