# 视频检测框回放与管理端轮询优化（2026-10-13）

## 改动范围

把视频分析时已有的 ByteTrack 人车检测结果接到管理员原片和候选证据片段的播放画面上。视频播放时间与抽样帧时间对齐；证据片段先加上它在原片中的起始秒数，再查找对应检测框。每个框显示目标类别、置信度和跟踪编号。

检测框只表示画面像素位置，不是地面坐标或路段定位。它只在已分析的抽样帧附近显示；没有框不代表该时刻没有目标。事故与积水候选的既有审核流程和路线发布规则没有变化。

## 长视频与管理端负载

- 分析结果最多保存 180 个预览帧，尽可能均匀覆盖整段视频。短视频约每秒一个预览帧；长视频按时长增加间隔，避免把 3 分钟以上视频的末段漏掉。
- 每个预览帧最多保留 80 个检测框。恢复检查点保留已完成分段对应的预览帧；过期或不匹配的旧检查点会因分析版本变化而重算。
- 每 5 秒刷新任务列表时，数据库查询和普通状态响应都排除逐帧检测框。只有管理员播放或拖动某个视频时，浏览器才请求该视频的预览帧；同一页面内共用一次加载结果。
- 逐帧预览接口要求管理员登录并返回 `private, no-store`。管理员播放视频期间暂停列表 DOM 重绘，暂停后再补上待更新任务状态；退出登录会停止播放并清理预览状态。
- 以前完成、但没有保存逐帧预览数据的旧任务不会自动补标；页面会说明该任务没有可显示的抽样检测框。需要看框时重新提交原视频分析。

## 识别能力边界

这次只让已有的人车跟踪输出可以在管理端回看，不训练新模型、不改变检测阈值，也不把检测框直接投到地图。暂无武汉大学无人机标注航次，因此不报告校内检测准确率、拥堵识别准确率或事件定位精度。管理员仍须查看原片、核对具体路段和有效时间后才能发布路况。
