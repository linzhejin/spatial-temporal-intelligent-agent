# 公开影像隔离试用与模型对比

记录时间：2026-11-09。本记录区分模型能否运行、隔离试用是否可用，以及是否达到校园正式启用条件。原有 60 号报告继续保留；本记录补充新的模型对比和试用实现，不把公开样本推断为校园精度。

## 当前结论

已经实现管理员公开影像试用：图片和视频可上传并由独立视觉 worker 分析，结果可人工确认、排除或记录漏检。试用任务不填写虚构的校园位置或拍摄时间，不能作为真实道路事件来源，也不会改变路线。正式校园巡查中的事故和积水模型仍受原有授权及现场验收检查约束，默认关闭。

目前公开样本上存在明显误报与漏报，且没有武大场景的独立航次真值，不能将这些模型作为可靠的正式路况告警。试用仅用于观察模型输出和收集人工复核意见，不代表模型已通过现场验收。

| 积水基线 | 既有十类模型在 32 张 FWISD 分层诊断图片上的道路像素 IoU 为 0.179；二类可见水体模型为 0.146。16 张无淹水道路标注图片中，分别有 4 张、15 张至少 8% 的道路像素被预测为水。这是像素诊断，不等于实际道路事件误报数。 |
| SegFormer B0 试用权重 | 基于 [NVIDIA SegFormer](https://github.com/NVlabs/SegFormer/blob/master/LICENSE) 与 [FWISD](https://huggingface.co/datasets/kevinxue112/FWISD) 数据进行非商业本地开发：冻结编码器，使用 95 张开发图训练、23 张开发图选择检查点。模型在同一批 32 张 FWISD 图像上按应用的 256 像素重叠切片流程推理，已知道路标注范围内像素 IoU 为 0.358、精确率 0.379、召回率 0.868；16 张无淹水道路图中 15 张至少 8% 的道路像素被预测为淹水。图像可能来自相近场景，未评估人工圈选误差。NVIDIA 源码条款限定非商业研究/评估，FWISD 标记 CC BY-NC 4.0；衍生权重仅供受限研究试用，未证明可用于正式服务。 |

时序事故权重本地转换为 ONNX 后，5 组相同输入的 PyTorch/ONNX 最大绝对分数差小于 `9e-7`；15 段 ACCIDENT 视频从原文件运行应用适配器，与先前 PyTorch 决策全部一致。转换后的文件 SHA-256 为 `15b720a755c75b446fb2765f4eeb653a0afd66de3f0884fd19d6c7d3f7889956`。积水试用 ONNX SHA-256 为 `ad1010ebdc83bef6e104fc360d683ea25b3325ce7d1d35fb4fc00acb14f19093`，单样本导出数值最大误差 `1.43e-5`。数值一致性不证明识别准确性。

## 隔离与运行方式

- 试用由 `VISION_TRIAL_ENABLED` 单独控制，默认为关闭；正式 `VISION_ACCIDENT_ENABLED` 和 `VISION_FLOOD_ENABLED` 不随之打开。模型文件在 Git 外配置，不提交公开素材或权重。
- 任务的 `purpose` 在创建后不能更改；数据库触发器确保试用结果带有旧版本也能识别的隔离标记。发布道路事件时服务器再次核对任务用途，即使管理员确认候选也会拒绝。回退旧版本前仍应排空试用任务。
- 时序模型仅支持视频，每个最多 40 秒的窗口均匀抽取 16 帧，相邻窗口重叠 20 秒；窗口内检测到线索时展示整个筛查范围，不生成可能漏掉事件的居中短片。40 至 45 秒视频的重叠窗口策略是本项目试用适配，尚无独立性能验收。
- 时序事故试用变量为 `VISION_TRIAL_ACCIDENT_KIND=temporal`、`VISION_TRIAL_ACCIDENT_MODEL_PATH` 和 `VISION_TRIAL_ACCIDENT_THRESHOLD`；积水试用使用 `VISION_TRIAL_FLOOD_MODEL_PATH`、`VISION_TRIAL_FLOOD_MODEL_ID` 和 `VISION_TRIAL_FLOOD_PROBABILITY`。管理员仅应在符合来源使用条件的私有非商业评估中配置经核对的文件；正式服务使用权与校园现场验收需另行完成。
- 实际检查情况分别记录为已检查、缺少观察区域、仅支持视频、无可用观察帧、未配置或失败。积水需要圈选路面；时序事故模型使用整幅视频抽帧，不依赖圈选区域。图片不能由仅支持视频的事故模型独立检查。
- 试用任务最多接受 2,073,600 像素的画面和 45 秒视频；积水视频每秒至多采样一帧。试用不运行人车检测，页面不会把零检测数误写为真实数量。可用独立 `VISION_WORKER_ROLE=trial` 进程领取试用任务；`operational` 进程只领取校园巡查任务，健康状态分别报告。

## 验证与原始证据

- 两个互相独立的本机 PostgreSQL 测试库分别用于自动化和浏览器联调。相关 Python 回归 531 项通过，2 项因主环境缺少 ONNX 依赖跳过；在独立 ONNX 环境对对应模块补测 4 项通过。管理台与 Service Worker JavaScript 检查 91 项通过。该次回归包含工作区中并行存在的姿态测试修改，不把这些修改纳入本次提交。
- 真实浏览器分别完成：公开图片上传、积水模型推理、候选确认与漏检记录；公开视频分块上传、取消、重试与推理；时序模型视频上传、真实推理和窗口证据显示；同一视频同时运行事故与积水模型。加上双 worker 进程联调，共 6 项通过。完成后试用任务不能转为真实道路事件。浏览器检查覆盖 360、390、430 像素；服务工作线程实际完成旧缓存升级和回退。
- 积水浏览器测试最初假定 `00324` 的已圈选路面必然生成 B0 候选，实际没有，测试因此失败；复核确认不同圈选区域可有不同输出，改用已标注淹水道路的 `00270` 和其道路外接区域验证候选复核流程。该样例是功能测试，不计入准确率。
- 服务器独立进程设 640 MiB 内存上限、不使用交换空间、CPU 配额 1 核：原有人车检测流程完成图片后在视频阶段触及上限，被该进程的 OOM 约束终止；线上三个既有服务继续运行。轻量专项流程在同一上限下依次完成图片、约 13 秒 1080p 全画面积水视频和约 30 秒事故视频，进程最大 RSS 约 521 MiB，耗时约 81 秒；这是一次受控容量检查，不代表所有素材或并发下的上限。
- 新增数据库字段后，使用上一个生产提交的实际代码读取试用任务并尝试发布，旧版本按隔离标记拒绝；试用和校园任务由两个真实 worker 分别领取并完成。回退时仍须先排空试用任务。
