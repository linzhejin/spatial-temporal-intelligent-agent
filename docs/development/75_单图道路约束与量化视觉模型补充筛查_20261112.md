# 单图道路约束与量化视觉模型补充筛查

日期：2026-11-12。本记录补充 66 至 74 号记录，不替代其原始失败证据。

## 结论与边界

继续使用同一批已经参与筛查的公开影像，检查了单张图上的自动道路约束及一个更大的量化视觉问答模型。两种尝试均存在明显漏报或误报，**自动免圈选候选继续关闭，生产仍采用人工圈选**。本次没有训练、使用付费算力、修改生产或开启事故模型。

这些图片已经用于模型筛选，不能作为独立测试或校园现场精度证据。公开标注存在其自身边界：落在标注道路以外不必然意味着真实世界没有道路；“正例有交集”只表示候选与标注淹水路面至少有一个重合像素，也不意味着完整检出。

## 单图道路约束

将 73 号记录中 SegEarth-OV 的积水提示，与同一张灾后图上 CurviWeave Massachusetts 道路预测相交。CurviWeave 固定 SHA-256 `02fe0885dc520f902f0f62f4c531eaeff2ad85d036e3e8b81f5702ddb7b17f73`，读取其公开检查点的 EMA 参数并严格匹配结构；两者都只读取当前 RGB 图片，不使用灾前图或道路标签。SegEarth 仍为未与作者 GPU 原实现数值对齐的 CPU 适配，不能据此评价作者原模型。

候选轮廓按本地原型生成，在 512×512 网格上近似栅格化后评分；统计轮廓时仅计入空洞轮廓完整的候选，边缘简化和网格转换有误差。道路阈值取原有的 0.5，另探索 0.05、0.1、0.2、0.3；这只是已有样本的阈值探索，不是独立调参或发布阈值。候选不等于已匹配的地理道路。

| 16 张 Delta 旧样本上的方法 | 8 张正例中候选与积水标注有交集 | 8 张无积水道路标注图片中出现候选 | 已标注积水路面被覆盖 | 候选轮廓落在道路标注外 |
| --- | ---: | ---: | ---: | ---: |
| 仅 SegEarth 积水提示 | 8 | 8 | 约 50.73% | 约 88.95% |
| 相交，道路阈值 0.5 | 2 | 4 | 约 2.40% | 约 4.04% |
| 相交，道路阈值 0.05 | 2 | 4 | 约 3.28% | 约 7.56% |

阈值 0.5 的道路模型在用户展示图上没有预测道路，因而组合后没有候选；阈值降到 0.05 后展示图出现一个候选，但该候选没有覆盖 16,879 个标注淹水路面像素，248 个显示像素均落在标注道路的非积水部分。将道路预测向外扩展 3 像素后，仍未覆盖该图的淹水道路。其余两张 Ian 积水图在这些设置下也没有与积水标注相交的候选。

该结果反映当前模型组合不能兼顾误报与漏报，并不证明所有单图道路提取方法都不适用。完整结果位于 Git 外 `D:\LuoJiaValidation\flood_auto_review_20261111\segearth_post_road_examples_diagnostic.json`、`segearth_post_road_validation16_diagnostic.json` 及同前缀 `_sweep.json`；脚本为 `diagnose_segearth_post_road.py`。

## SmolVLM 500M 量化模型

另筛查 [SmolVLM-500M-Instruct](https://huggingface.co/HuggingFaceTB/SmolVLM-500M-Instruct) 的官方 ONNX 权重，模型修订 `a7da5b986cb59b408707209984f360a5f4ad7e47`，发布页标注 Apache-2.0：

- `decoder_model_merged_q4.onnx` SHA-256 `6d64c0fdce1c3515c40a08ff8e398bfbc0b2e961ae46d1b84b91e6a7b269b9d1`。
- `vision_encoder_q4.onnx` SHA-256 `179812d5b1315edbe3e7164ea3d847c52723692e83ac9c770a5234962663fcad`。
- `embed_tokens_int8.onnx` SHA-256 `f5f14887bf9b756d9fff2e412d474f0b5403e91f33b23460c9411f0ca54d945b`。

本机使用 Transformers 4.57.0、ONNX Runtime 1.23.2、CPU 两线程；按模型发布方提供的 `longest_edge=512` 设置处理 512×512 原图，确认视觉输入为 `[1, 1, 3, 512, 512]`。ONNX 会话和逐词生成流程参考发布方 SmolVLM 量化推理示例；本次未与 FP32 原模型逐图数值对齐。

固定问题为“这张航拍图是否存在被洪水覆盖的道路？回答 YES、NO 或 UNCERTAIN”，采用贪心生成，并在生成后才读取道路标注：

- 四张已使用过的 Ian 图片中，3 张有积水道路标注，模型只对展示图回答“有”；一张没有积水道路标注的图片回答“没有”。
- 十六张已使用过的 Delta 图片中，8 张有积水道路标注，只有 1 张回答“有”；8 张没有积水道路标注，其中 2 张回答“有”。没有出现无法解析的回答。
- 该模型只给整图回答，不生成积水道路边界。当前实验提示其作为前置过滤会漏掉许多正例，也不能单独完成自动候选。

两次 Windows 进程峰值工作集分别约 1062 MiB；包含 Python、预处理库和三个 ONNX 会话，不能换算成生产 Linux 640 MiB cgroup 占用，也不证明任何其他部署方式无法满足限制。逐图结果、固定权重和脚本均保存在 Git 外 `D:\LuoJiaValidation\flood_auto_review_20261111`，文件前缀 `smolvlm_500m_onnx_512_`，脚本为 `diagnose_smolvlm_500m_onnx.py`。
