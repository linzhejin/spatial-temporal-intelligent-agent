# 管理台事件表单交互修复（2026-10-12）

## 范围与版本状态

针对 `/manager` 的道路事件发布表单，基于 `origin/main` 的 `0f1f729` 在独立工作区修复，发布前正常合并远端 `568cc28` 的影像观察区提示改进。未修改桌面仓库中另一条对话的文档、科研数据或采集任务。此记录说明本地实现与验证，推送与部署状态以文末发布记录为准。

## 问题与变更

- 原生 `select multiple` 在电脑上要求按 Ctrl 多选，选中状态也不直观。恢复为三个独立复选卡片，可直接点击或触摸、多选，也可用键盘操作。不默认全选，避免误影响全部出行方式。
- 原先两个空白的 `datetime-local` 输入框依赖浏览器的组合日期时间控件，没有常用有效期。改为默认“发布后立即生效，持续 30 分钟”，提供 1 小时、2 小时、至开始当天结束及自定义结束时间。指定开始或结束时间时分别填写日期与时刻，不必通过组合弹窗完成。
- 人工事件可明确选择“长期，手动结束”；影像来源事件不允许长期有效，转入表单时重置为 30 分钟，并继续要求实际道路确认和不少于 8 字的现场依据。
- 有效时间按北京时间 UTC+8 展示、解释，再转为 ISO UTC 提交，与浏览器所在时区无关。结束时间须晚于开始时间且尚未过去；常用时长以实际点击发布时的开始时间计算。
- 发布按钮旁明确显示缺少的事件类型、名称、路线处理方式、出行方式、道路确认、现场依据或时间错误。缓行倍数须为 1–5，最多一位小数；隐藏的缓行、日期和时刻控件不参与浏览器必填校验。
- 增加发布中的独立状态，输入事件不能重新启用发布按钮；失败保留草稿和道路，便于重试，成功清理选择与来源。现有 `notice/slowdown/closure` 与 `affected_modes` 接口不变。
- CSS 和 JavaScript 地址均更新为 `v=20261012-event1`，区别于另一个已发布改动使用的 `20261012b`，防止浏览器复用旧表单逻辑。未改依赖、数据库迁移、模型、道路数据、权限或事件持久化方式。


```powershell

$env:RUN_MANAGER_BROWSER_TESTS='1'
python -m unittest discover -s tests/browser -p test_manager_event_controls.py -v
Remove-Item Env:RUN_MANAGER_BROWSER_TESTS
```

## 用户操作

1. 填写事件类型和名称，选择提示、缓行或禁止通行。
2. 直接勾选现场确认受影响的出行方式。
3. 常见短期事件保持“立即生效 + 30 分钟”或换为所需时长；需要特定起止时间时再选择指定开始、自定义结束。
4. 点击“选取路段”，在地图上选路并核对高亮，点击“确认路段”。影像来源还要填写现场依据。
5. 按钮提示“信息已齐全”后发布。若仍置灰，按旁边提示补齐；失败后无需重填，直接重试。
