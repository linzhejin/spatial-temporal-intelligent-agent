# 无人机事故与积水模型接入及评测

## 可加载模型约定

视觉 worker 只从本机路径加载 ONNX；上传影像不会触发联网下载。事故模型与积水模型各自加载、各自报错。任一可选模型权重缺失、格式不符或推理失败时，基础人车检测仍可继续。

| 能力 | 输入和输出约定 | 结果边界 |
|---|---|---|
| 事故场景分类 | 单输入 `[N,3,H,W]`、固定 RGB 224×224、ImageNet 均值/标准差归一化；输出五类分数，顺序为 `collapsed_building, fire, flooded_areas, normal, traffic_incident` | 输出画面级线索。连续画面达到阈值才生成待审核候选，不表示事故车辆坐标或现场道路已定位 |
| 道路积水分割 | 单输入 `[N,3,H,W]`、固定 RGB 尺寸；输出 `[N,10,H,W]`，FloodNet 第 3 类（从 0 开始）为 `flooded_road` | 只处理管理员圈定的“路面”区域；输出画面像素占比和轮廓，不推测真实面积或水深 |

每一模型的 ONNX 输入尺寸、输出维度和类别数在加载时检查。管理台显示实际视觉 worker 能力，不根据配置文件里写了路径就误报“已启用”。

## 测试集清单

评测工具不自行随机拆分帧。清单必须登记按航次、独立场景或事故事件分组的训练、验证和测试组；三组不能重叠，样本必须属于测试组。清单中填写相对于 `--dataset-root` 的文件路径。

```json
  "dataset": "AIDER local held-out test",
  "split_unit": "incident_scene",
  "split_groups": {
    "train": ["scene-001", "scene-002"],
    "validation": ["scene-003"],
    "test": ["scene-004", "scene-005"]
  },
  "class_order": [
    "collapsed_building", "fire", "flooded_areas", "normal", "traffic_incident"
  ],

    {"image": "test/scene-005/frame-010.jpg", "group_id": "scene-005", "label": "normal"}
  ]
```


## 视频事故事件级评测

静态 AIDER 分类指标不能代替“上传一段视频后，是否检出一个真实事故事件”。事故候选验收使用完整视频和独立航次分组，调用与视觉 worker 相同的 `analyze_media` 管线，再按**同一观察道路区域＋时间区间 IoU**做一对一匹配。一个候选不能匹配两个真值事件；重复候选计为误报，未匹配的真值事件计为漏报。

清单每个视频是一段经人工标注的事件片段；正例列出事故起止时间，负例用空 `events`。每个视频须先在观察画面上标记 `vehicle_lane` ROI。训练、验证、测试按完整航次或独立场景分组，不能把同一航次的相邻片段拆到不同集合。测试阈值必须先在验证视频上确定，再显式传入，不能看完测试结果后回调阈值。

## 视频中的触发式加密事故分析

常规视频检测仍按配置的 `VISION_SAMPLE_FPS`（默认 5 fps）采样。积水分割保持每秒一次；事故场景分类按每秒一次做常规抽查。当常规事故分数达到 `VISION_ACCIDENT_DENSE_TRIGGER_THRESHOLD`（默认 0.5）时，在后续 `VISION_ACCIDENT_DENSE_WINDOW_SECONDS`（默认 2 秒）内，对已采样的画面额外运行事故分类器，之后恢复常规频率。检测器本身的采样率不变，只有事故分类器加密；积水计算不会随之增加。

该触发阈值只是**决定多看几帧的计算调度阈值**，不等于事故候选阈值。候选仍由 `VISION_ACCIDENT_THRESHOLD`（模型默认 0.85）以及跨帧时间聚合规则判定；低分触发不得单独生成事故候选。触发窗口会保存在视频分段检查点中，任务续算时延续原有窗口。加密分析只能增加对短暂线索的观察机会，不能弥补场景分类模型缺少事故车辆定位的限制，也不构成准确率保证。

报告包含模型和清单 SHA256、逐类分类结果或路面 ROI 像素 IoU、推理时间及按清单分组重采样得到的 95% 区间。重采样组数不等于独立航次或事件数；必须结合清单中的 `split_unit` 解释。测试组少于两个时，置信区间标为空，不能用帧数伪装成独立样本数。

## 训练与授权边界

- [TakuNet 的 AIDER 数据读取器](https://raw.githubusercontent.com/DanielRossi1/TakuNet/main/src/datasets/aider.py)按类别目录排序读取五类；其仓库配置不能代替本项目的航次/场景级留出验证。本项目没有复制其代码或权重。
- [FloodNet 官方仓库](https://github.com/BinaLab/FloodNet-Supervised_v1.0)提供灾后无人机影像和语义分割标注，可用于公开集基线；自然灾后影像与校园浅积水差异很大，公开指标不能直接作为武大效果。
- 仓库现已加入 FloodNet 数据清单生成器、MobileNetV3-small＋轻量 U-Net 训练器、类别/像素评测、ONNX 导出和 CPU 数值一致性检查，入口为 [`scripts/vision/prepare_floodnet_manifest.py`](../../scripts/vision/prepare_floodnet_manifest.py) 与 [`scripts/vision/train_floodnet.py`](../../scripts/vision/train_floodnet.py)。训练依赖必须放在独立训练环境，不加入 Flask 或线上 worker 依赖；数据、检查点和 ONNX 均保存在仓库外。
- 当前公开数据实际使用情况及结果见下文“FloodNet 公开基线”。训练/测试按 398 个有像素掩膜的图像 ID 划分为 278/60/60；原始公开档案没有航次或场景 ID，所以这只能作为图像级留出结果，不能声称独立航次泛化。公开洪灾场景与武大雨后浅积水有明显域差异，且当前公开留出结果未达到预设目标，积水模型保持关闭。
- AIDER 的公开图像级分类基线已经训练和留出评测，但事件级、校园级效果与影像/衍生权重使用权仍未核实；相关数据、检查点和 ONNX 不得提交或部署。TakuNet 代码有独立许可，当前训练流程未复制其代码或权重。
- 当前车辆和行人视频跟踪器接入了固定上游提交 `FoundationVision/ByteTrack@d1bf019` 的最小 NumPy/SciPy 适配版，保留卡尔曼预测、高低置信度两阶段关联与线性分配；关联前将检测框按已有单应变换投影到视频片段的稳定参考帧。由于替换了上游 `lap`、`cython_bbox` 和 PyTorch 接口，这不是原仓库的原样安装包。授权与改动见 [`vision/vendor/bytetrack/THIRD_PARTY_NOTICES.md`](../../vision/vendor/bytetrack/THIRD_PARTY_NOTICES.md)。当前只有代码级回归，没有武大航拍跟踪数据或事件级拥堵精度，因此不宣称达到 ByteTrack 论文基准，也不据此单独发布拥堵管制。

事故和积水结果默认仅进入管理员逐条复核。管理员确认具体路段、出行方式和有效时间之前，任何识别结果都不会直接改变用户路线。

## FloodNet 公开基线（2026-10-10）

- 数据来源为 Hugging Face 上的 FloodNet 镜像，原始项目为 FloodNet-Supervised-v1.0，数据许可记录为 `CDLA-Permissive-1.0`。本机仅将数据解压到 `D:\\LuoJiaExperimentData\\WHUWalker_vision_research`，未复制到代码仓库或生产服务器。
- 首轮 CPU 训练 8 个 epoch 后，原训练评估在图像级留出集上 `flooded_road` IoU 为 **0.00061**、召回率 **0.000612**、精确率 **0.1723**，不具备筛查价值。ONNX 数值一致性检查通过只证明导出正确，不代表识别质量通过。
- 首轮检查发现训练集中 278 张图仅 23 张包含 `flooded_road`；第二轮加入正样本图像加权抽样和正样本像素裁剪。第二轮训练 8 个 epoch 后选出最佳检查点（验证 flooded-road IoU **0.0749**），并用项目实际 ONNX 路面推理流程重新评估 60 张留出图：`flooded_road` IoU **0.071639**，精确率 **0.071885**，召回率 **0.954420**，每图平均 IoU **0.029039**；按图像 ID 聚类 bootstrap 95% 区间 **[0.018444, 0.129880]**。高召回伴随大量误报，远未达到方案预设 IoU 0.60，因此该模型**不具备当前启用条件**。评估耗时 241.44 秒，约 4.02 秒/图（CPU）。
- 官方测试网格对齐检查发现 60 张留出图中 51 张原本同尺寸，9 张需要将 RGB 原图插值到标签网格；类别掩膜保持原样，没有对标签做重采样。评估报告保存在本机研究目录，不包含于代码仓库。该拆分只能称为图像级留出，不证明跨航次或跨场景泛化；灾后洪水影像也不能代替武大雨后浅积水样本。
- 后续又新增 `scripts/vision/calibrate_floodnet_threshold.py`，只在 60 张验证图上以路面 ROI 像素 IoU 选择类别概率阈值，不接触测试集；验证最优阈值为 **0.27929688**，验证 IoU **0.063755**、precision **0.070373**、recall **0.404023**。将阈值冻结后，在原 60 张图像 ID 测试集只评估一次：IoU **0.084187**，每图平均 IoU **0.019925**，precision **0.101286**、recall **0.332758**，按图像 ID 重采样 95% 区间 **[0.029481, 0.129851]**。测试结果相较原 argmax 的 IoU 0.071639 有小幅提高，但像素 precision 仍仅约 10%，远低于 IoU 0.60 的启用门槛；调阈值没有解决模型的误报和外域差异。`VISION_FLOOD_CLASS_PROBABILITY_THRESHOLD` 必须保持未设置，模型仍不启用。
- 校准和留出评测报告写在本机研究目录，不进入 Git。该阈值只对这一模型哈希、数据处理和像素目标有效，不能移作校园积水阈值；FloodNet 拆分单位仍是标注图像 ID，不代表独立航次或校园道路事件。
- 复现入口：先运行 `prepare_floodnet_manifest.py` 生成清单，再在独立 PyTorch 环境执行 `train_floodnet.py --dataset-root <解压目录> --manifest <清单> --output-dir <仓库外目录> --pretrained`。模型、数据清单 SHA256、逐类指标、配置和 ONNX 校验结果由脚本写入训练输出目录。
- 事故能力保持关闭，直到数据/权重使用权、按独立事件的评测和校园适用性达到验收标准。积水能力也保持关闭，直到校园样本和独立场景评测达到验收标准。可选模型不可用或失败不得影响普通人车检测、管理员上传审核和路线规划。

## AIDER 事故场景公开基线（2026-10-10）

- 本机研究目录已保存 AIDER 解压数据、MobileNetV3-small 训练结果和 ONNX 评测结果；数据与权重位于 `D:\LuoJiaExperimentData\WHUWalker_vision_research\AIDER_*`，未提交到 Git，也未部署到腾讯云。训练产物目录为 `AIDER_artifacts\mobilenetv3_run_20261010_seed20261010`。这是外部本机数据，不是仓库内可复现附件。
- 当前训练清单采用 3,788/520/2,121 张图像的 train/validation/test 划分，并将完全相同的 SHA-256 图像放在同一 split；排除了 2 组跨类别完全重复图像。AIDER 没有航次、事故事件或场景 ID，近似重复图像也未聚类，所以该拆分**不能证明跨事故事件或跨航次泛化**。
- 在 2,121 张图像级留出测试集上，验证集选定阈值 0.87921935；独立 ONNX 推理报告给出事故场景分类 precision **0.9291**、recall **0.8551**、F1 **0.8906**（TP 118、FP 9、FN 20）。按精确图像哈希组 bootstrap 的 95% 区间为 precision **[0.8788, 0.9710]**、recall **[0.7926, 0.9077]**；两个区间下限均未达到预设的 0.90/0.80。点估计只能作为公开静态影像初始基线。
- AIDER 的 `traffic_incident` 是整幅画面的场景标签，不标事故车辆或具体道路。它不能证明一个视频事件发生在某条校园道路，也不能单独触发路线管制；报告中的 `route_event_activation_eligible` 为 `false`。完整汇总、混淆矩阵、模型与清单 SHA256 保存在上述本机输出目录。
- AIDER Zenodo 页面同时出现 CC-BY-4.0 元数据及“© 2020 IEEE、个人使用、其他用途需 IEEE 许可”的说明；来源图像由不同网络来源收集，故本项目把影像再分发和训练权重公开部署权利视为**待澄清冲突**，不把元数据标签当成可公开部署许可。[AIDER 数据记录](https://zenodo.org/records/3888300) TakuNet 仓库代码另用 CC BY-NC-SA 4.0；本项目当前训练使用自己的 torchvision MobileNetV3-small 流程，没有复制其训练代码。[TakuNet 官方仓库及许可](https://github.com/DanielRossi1/TakuNet)
- 更贴近事故车辆定位的候选是 DARS：其仓库说明包含事故参与车辆与普通车辆的实例标注，并按事故事件划分；完整图像集因来源权利限制不能公开分发，允许用于非商业学术研究的子集需向作者申请，当前仓库也没有公开该子集的划分文件。因此 DARS 是需要导师确认并取得授权的后续数据选项，当前不能作为已下载、已训练或已验证的项目能力。[DARS 官方仓库与数据说明](https://github.com/yrrril/DARS-Aerial-Accident-Instance-Segmentation)

**处理结论：**AIDER 基线的训练与图像级测试已经完成，但事故事件级、校园级和权利验收仍未完成；不启用事故权重。待取得明确的数据/权重使用授权和按独立事件标注的航拍样本后，再进行事件级评测与管理员复核流程校准。

## Floodwater 二分类可见水体实验（2026-10-11）

- 新增公开数据流水线：[`prepare_floodwater_training_data.py`](../../scripts/vision/prepare_floodwater_training_data.py)按源视频分组生成清单并抽帧，训练入口 [`train_visible_water.py`](../../scripts/vision/train_visible_water.py)训练背景/可见水体二分类，评估入口 [`evaluate_visible_water_manual.py`](../../scripts/vision/evaluate_visible_water_manual.py)只在独立人工标注目录报告结果、不调阈值。数据来自 [Floodwater Dataset 官方仓库](https://github.com/decide-ugent/floodwater-dataset)，数据许可标记为 `GPL-3.0-only`；影像与权重均不进入 Git 或生产服务器。
- 训练清单按 **22/4/5 个源视频**分配训练/验证/测试组，训练只取前两组中的 1 fps 帧，共 **6,390** 张训练、**1,204** 张验证图；5 个测试视频没有抽取任何帧用于训练或选模。训练标签属于 SAM2 辅助生成的伪标签。复现清单 SHA256：`8e69f1b213acc1f54b0a5b34c5c0d3b1e912e969fb27cce89c9387d9b4ad386d`。

- 人工标注集的目标是**所有可见水体像素**，不是路面专属积水，也不是武汉大学的浅水/积水；公开洪涝影像与校园道路的成像、背景和水体尺度不同。因此上述指标**不能据此宣称“道路积水识别达到 IoU 0.60”**，也不能让候选自动影响路线。ONNX 输入为 256×256，CPU 导出/推理数值差异最大值 `0.0004945`，通过导出器设定的 `rtol=1e-3, atol=1e-4` 一致性校验；模型 SHA256：`62688f10726fa0bb75b2a57e9762e5544c46a6166699d896343f41e8c91dbe65`。
- `OnnxFloodSegmenter`现兼容二类可见水体及既有十类 FloodNet 输出；二类结果只称为“圈定路面画面内的可见水体线索”，疑似事件逐项由管理员复核，明确说明模型不能区分路面积水与其他可见水体。线上未配置此模型，自动发布和路线管制保持关闭。用于复现的权重保存在仓库外 `D:\\LuoJiaExperimentData\\WHUWalker_vision_research\\Floodwater\\visible_water_run_20261011`，人工集报告保存在同目录 `reports\\visible-water-binary-manual-eval-20261011.json`。
- 后续验收仍需校园雨后航拍并按**航次/地点**隔离留出集，标注路面范围内的浅积水、湿路反光、阴影、湖面和普通干路反例；评估道路 ROI 水体 IoU、误报率、漏报率及无法判断比例后，才能讨论上线开关。GPL-3.0 数据及衍生权重的发布/部署权利须先核实。

## 武大校园道路可见水体评测清单

`train_visible_water.py` 现也接受这个任务的训练清单：`samples` 只能包含训练与验证航次，`split_groups.test` 只声明留出航次、不放入任何测试帧；必须声明 `label_source: "manual"`。训练器拒绝重复使用同一架次、测试帧泄漏、越界文件路径及非法道路多边形。它仍只用训练/验证帧选检查点，模型权重和数据保存在仓库外。

训练时二值掩膜会按 `road_surface_polygon` 裁到道路区域；训练随机裁块优先以道路内水体或路面像素为中心。验证暂用每张图一个固定裁块（校园数据以道路 ROI 中心取块）选择检查点，不作为最终精度；最终结果必须用完整原帧和全道路 ROI 的 `evaluate_specialized.py` 测试入口报告。

启动模型前，训练入口会预检每个训练/验证图像与掩膜是否存在、能否解码、尺寸是否一致，掩膜是否为 PNG 且只含 0/255，道路多边形是否有面积；解析到数据集根目录外的符号链接会被拒绝。它还计算输入内容摘要，并拒绝跨训练/验证 split 的完全相同图像，避免这类显式重复造成留出泄漏。失败时不会创建模型输出目录；报告记录验证样本数、字节数和输入内容摘要。近似重复帧仍需要按航次、地点和时间间隔人工检查。
