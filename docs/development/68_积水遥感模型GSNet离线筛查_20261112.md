# 积水遥感模型 GSNet 离线筛查

日期：2026-11-12。此记录补充 66、67 号记录，不修改先前原始结果。

## 决定

新增候选 [GSNet](https://github.com/yecy749/GSNet) 已在本机 CPU 适配下运行，但样本内仍有明显漏报、误报，且未经作者原始 GPU 实现的数值对齐；不能作为免圈选功能的发布依据。当前自动候选原型保持禁用，生产流程未改变。本次没有训练、调用付费资源或修改生产系统。

## 模型及运行方式

- 作者公开的源码修订为 `61da3017529a99f8ae1bad5d423e62e2c7484e36`，模型 `GSNet_base.pth` 从作者仓库链接的公开文件取得；文件 SHA-256 为 `23d6787b99856dbd02134f624c89ff43885d6cb1ab888272cec5314524d2259a`。下载后校验 ZIP 条目的 CRC 及远程元数据一致；作者页面未给出可核对的文件哈希。源码仓库未见明确许可，产品使用权限待确认。
- 公开模型权重文件约 1,153 MiB；仅读取元数据统计，模型自身 FP32 参数约 931 MiB，超过现有视觉任务 640 MiB 的总内存上限。参数大小并不是完整运行内存。作者的实现包含直接调用 CUDA 的路径。
- 在本机独立 Python 环境，用 PyTorch 2.13 CPU 加载权重，模型张量严格匹配；根据上游配置使用 RGB、短边 640、模型内部 384 输入和 FloodNet 10 类。为本机筛查，最小化实现了单图所需的 Detectron2 图像填充和结果缩放，并将文本编码的 CUDA 操作替换为 CPU 操作。原始模型 Python 源文件没有被修改；该适配尚未与作者原始环境逐像素比较，不可当作作者实现的正式指标。
- 本机这次 CPU 流程的 Windows 进程峰值工作集约 2,213 MiB；不等于 Linux cgroup 结果，也不能证明压缩模型一定无法满足限额。是否能量化或转换，需要另做数值、效果和资源验证。本次未将其接入产品。

## 图片筛查

先在用户展示图和另外 3 张已使用过的 Hurricane Ian 图片上运行。直接按 10 类最大输出确定类别时，4 张图都未检出淹水道路。阈值扫描发现低分区域有部分真实积水路面的响应，但单凭这一组图选择阈值会过拟合。

随后从先前使用的 64 张 Hurricane Delta 图片中，按已有标注确定性抽取 8 张含淹水道路和 8 张未标注淹水道路的图片。标注只用于平衡抽样及推理后评分，没有作为模型输入。这是探索筛查，样本量小、已参与先前诊断，不能当独立测试或校园现场精度。

对 GSNet 输出使用图像空间轮廓生成、每张最多 24 个候选；对照为先前同一批图片上的 v7 自动候选结果。两种方法的模型输入和输出分辨率不同，以下是同图诊断，不是完全等处理的正式模型对照：

| 方法 | 轮廓中落在标注淹水道路上的像素 | 标注淹水道路被轮廓覆盖 | 轮廓落在道路标注之外 | 8 张干燥道路图中出现候选 |
|---|---:|---:|---:|---:|
| v7 自动候选对照 | 3.23% | 4.73% | 93.66% | 8 |
| GSNet 最大类别 | 23.45% | 11.90% | 76.55% | 2 |
| GSNet 分数阈值 0.01 | 17.12% | 15.72% | 41.04% | 7 |
| GSNet 分数阈值 0.03 | 22.44% | 5.23% | 25.55% | 4 |

其中“干燥道路”表示该公开标注没有淹水道路；“出现候选”表示至少一个轮廓，不是经过人工确认的事件级误报。上述像素指标按样本汇总，分母分别为轮廓像素或标注淹水道路像素。按最大类别，8 张正例只有 3 张的候选与淹水道路标注存在任何像素交集。当前结果不足以支持自动候选上线；也不能据此断言 GSNet 在原作者数据、原始实现或其他地区的性能。
