# 自动积水轮廓修复及三组模型筛查

日期：2026-11-12。本记录补充 66 至 70 号记录，保留其原始失败证据。

## 当前结论

隔离原型修复了自动候选轮廓会填满内部空洞的问题，并补充了三个公开权重的离线筛查。模型筛查仍有明显漏报、误报；**自动免圈选能力继续关闭，修复未部署，现行人工圈选流程不变**。事故模型未开启。

下面的公开样本已参与过前期诊断。它们用于发现问题，不是独立模型测试、校园精度或 Linux 资源验收；道路标注之外也不能机械等同于现实中没有道路。没有训练模型或使用付费算力。

## 轮廓问题及修复

原型对模型分类结果只提取外轮廓，候选展示时会把区域内部未被模型判为积水的空洞也填上；内部独立连通区域还可能被外轮廓检索漏掉。候选的平均分也原先混入了外轮廓内部的非候选像素。

修复后，连通区域分别保存外边界及内部空洞，分数只按对应连通区域的模型像素计算；浏览器以偶奇填充方式显示空洞，并将绘制限制在外边界内。最多记录 128 个空洞、合计 4096 个顶点；数据不完整、无效或超过上限时只显示外边界，并说明内部形状未完整显示。旧候选无空洞数据时也只显示边界。其余候选数量上限、人工复核、道路边绑定、公开试用不可发布等限制不变。

以展示图 `HURRICANE-IAN_000491` 为例，在 512×512 网格上近似栅格化比较，原先轮廓中有 22,732 个像素不在模型原始分类结果内；保留空洞后为 8,178 个，减少约 64.02%。但修正后仍有约 87.02% 的候选填充像素位于公开道路标注之外，且轮廓简化和网格换算仍存在偏差；这不是识别质量达标的证据。未标注淹水道路的对照图仍产生 23 个候选。

图像、逐图结果、原始模型输出与脚本保存在 Git 之外的 `D:\LuoJiaValidation\flood_auto_review_20261111`，其中包括 `polygon_inflation_examples.json`、`polygon_inflation_validation16.json`、`polygon_holes_examples_diagnostic.json` 和对应 `diagnose_*.py`。真实浏览器结果的截图保存在 `tmp_geometry_browser_20261112b`。

## 新增模型筛查

统一检查先前用过的 4 张 Hurricane Ian 图片及 16 张 Hurricane Delta 图片；后者是先前依据标注确定性选出的 8 张含淹水道路、8 张未标注淹水道路的图。标注仅用于既有样本选择和推理后的计分，不输入模型。下表“正例有交集”只表示至少一个候选像素与标注相交，不等于完整检出；“负例有候选”也不是已确认的事件级误报率。

| 公开权重 | 16 张中正例有交集 | 16 张中负例有候选 | 标注淹水道路被候选覆盖 | 候选落在道路标注之外 |
|---|---:|---:|---:|---:|
| echonoshy UNet | 1/8 | 4/8 | 约 0.043% | 约 99.94% |
| echonoshy DeepLab | 0/8 | 0/8 | 0% | 无候选 |
| AWS Hack UNET-X | 2/8 | 6/8 | 约 0.499% | 约 94.26% |

echonoshy 两份文件来自[作者的 v0.1.0 发布](https://github.com/echonoshy/floodnet-segmentation/releases/tag/v0.1.0)，均核对了作者公布的 MD5：

- UNet：MD5 `ea5cb3c44949cb90b761de639d930ee7`，SHA-256 `92b6b32e2e3ac6352bb6123c7208460b17e64433b7d148161f5dd1e92dec9b8f`。展示图产生 18 个候选，候选与淹水道路标注没有像素交集，候选均在道路标注之外。
- DeepLab：MD5 `ec135b70cb54b1c4c40bbe08ce21d467`，SHA-256 `80a3df25a6b5836c4339062b1ea8bd3b65397f8b8ecb7d9d579aa26cf47e9dc1`。4 张 Ian 图片均未形成候选。

两者在本机使用作者发布时配置及权重内记录的 256×256 图像处理参数，严格匹配权重结构；仅允许检查点中的已知配置对象按惰性容器读取。UNet 代码取自发布修订 `90af20e`，DeepLab 结构按该修订的代码使用 torchvision。当前 PyTorch 2.13 CPU 环境与作者记录的 2.1 环境不同，未做原环境数值对齐；仓库未明确模型使用许可。

[AWS Hack Flood Damage](https://github.com/hamdaan19/AWS-Hack-Flood-Damage) 的 UNET-X 固定源码修订 `7b896e30eed0d104da88e1619a140f0f2a0951b6`，检查点数据文件 SHA-256 为 `52e2152b38e03455d4d2a162be4ad5032f28b4f5282519fc52a542c26f60b1e8`，索引 SHA-256 为 `95aa722d23a8a29209b324f1d50f0f5faaf5501d084d6a6c8bd913581e8d0113`。使用 TensorFlow 2.10.1 CPU，按作者代码将 RGB 原值分成 240×320 图块并补零，拼接后裁回原图，模型变量加载检查通过；尚未与作者环境逐像素对齐。展示图生成 6 个候选，仅覆盖 16,879 个标注淹水道路像素中的 99 个；未标注淹水道路的 Ian 对照图生成 2 个候选。该仓库采用 GPL-3.0，具体权重和数据的使用条件仍需核实。

另外在 6 张 FloodNet 训练分区图片上做处理链检查：三份权重均在 4 张带淹水道路标注的图中输出了部分相交像素；AWS UNET-X 的这些图片先缩放到 512×512 再分块。这些图可能与训练重叠，只能辅助检查输入与输出，不能当作泛化成绩。三个模型的逐图结果、文件哈希、原始输出和脚本均保存在上述 Git 外目录，文件前缀为 `echonoshy_unet_`、`echonoshy_deeplab_` 和 `aws_flood_`。未进行 Linux 640 MiB、75% CPU、无交换空间验收或产品接入。

## 工程验证

- 独立 PostgreSQL 自动化库：自动候选、Doodleverse 适配、视觉分析、worker、任务及道路事件相关检查共 195 项通过。
- JavaScript 全套：238 项通过；包含空洞、独立内部区域、超出限制降级、旧数据降级和非法空洞坐标。
- 真实 Doodleverse 权重、独立 PostgreSQL 浏览器库：公开图片上传、实际 worker 函数处理、候选展示、确认及试用结果禁止发布通过；390 像素真实浏览器还检查空洞透明、有效区域可见、超出外轮廓的区域不被绘制。该测试对工作线程能力进行隔离注入，不等于正式 worker 自动能力验收。
- 同一独立浏览器库顺序执行真实图片管理流程：自动提示候选与人工圈选的缓行、封闭三项通过，覆盖审核、选路、发布、撤销和相应路线效果；测试事件仅在隔离环境创建。
- 按现有人工圈选清单正常启动真实 worker，试用与校园图片任务均完成；工作线程心跳明确不开放自动候选能力。1 项通过，不代表自动模式已验收。
- 真实 Service Worker 从生产基线 `e999892` 升级到候选缓存再回退：1 项通过。

首次并行启动浏览器与缓存测试时，两个 pytest 进程误用同一临时目录，分别出现 Windows 文件占用和文件消失；这是测试隔离错误，未连接生产库。随后为不同测试指定独立的新临时目录，且自动化与浏览器使用不同测试数据库，上述检查已重新实际执行。原失败记录不作为通过证据。
