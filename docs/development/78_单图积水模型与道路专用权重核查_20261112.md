# 单图积水模型与道路专用权重核查

日期：2026-11-12。续 66 至 77 号记录，原始失败记录保持不变。

## 结论

新增实测一份 RGB 分割权重，结果不支持将其用于自动积水道路候选。另一份公开 SavedModel 的实际输入输出与发布的单图示例不一致；还发现一个直接识别淹水道路的单图方案，但在其公开源码快照和相关发布说明中未找到可直接下载的训练完成权重。

本次没有训练模型、使用付费资源、变更生产或开启事故模型。免圈选原型仍保持关闭；下述已用样本均属探索筛查，不是独立测试或校园精度评价。

## RGB SegFormer 实测

- [模型发布库](https://huggingface.co/abiramikandasamy03/aifloodsense-flood-model)固定修订 `7e7d690627b27e196040af52e22bb3959cf84a67`，`model.safetensors` SHA-256 为 `dbae69453c9ec6368cfdfc47d19842b25f20ba44b0e71a57893002d0d7711dca`，与发布 API 的 LFS 摘要一致。配置和图像处理器文件也核对了源 Git blob 标识。
- 发布库无模型卡、许可、训练集和类别语义说明。配置没有 `id2label`，加载后只有 `LABEL_0` 与 `LABEL_1`；不能仅凭模型名称认定它与同名论文权重相同，也不能将任一输出类别直接宣称为可靠的积水道路类别。发布配置记录 Transformers 5.17.0；本次使用 5.13.0、PyTorch 2.13.0 CPU，权重严格匹配，未与作者环境逐像素对齐。
- 输入遵照发布的处理器：512×512 RGB、缩放至 0—1 并按 ImageNet 均值和标准差归一化；将两类分数双线性上采样到原图后取最大类别。推理不读取标注；两类结果分别记录，不能根据这批结果反推作者类别定义。

用户展示图上，类别 1 主要覆盖可见河道。按原型轮廓近似栅格化后产生 18 个候选，覆盖 16,879 个标注淹水道路像素中的 645 个；26,279 个候选像素中 25,634 个在道路标注之外。类别 1 与 SatLens 自动道路直接相交后未产生候选。类别 1 在另一张没有淹水道路标注的 Ian 对照图上也产生 13 个候选。

16 张此前参与过筛查的 Delta 图片中，8 张有淹水道路标注、8 张没有。原型最多展示 24 个候选，统计轮廓简化及网格换算有误差；未出现空洞不完整。道路标注之外不必然等于现实中没有道路，没有淹水道路标注也不等于全图没有洪水。

两类均不满足当前目的；表格不能用于确定输出语义或推断其他影像上的表现。也记录了 UPerNet 道路直接相交与 3 像素邻近探索，其许可及预处理限制见 76 号记录，均未接入产品。Windows 进程记录的本次 16 张推理峰值工作集约 1,170 MiB，不等于 Linux 父子进程 cgroup 资源验收。

## 其他方案核查

### 发布示例与 SavedModel 签名不一致

[AndrewMaru 的 U-Net 发布库](https://huggingface.co/AndrewMaru/unet-flood-segmentation)修订 `d9b74f38c48f5c3ca51c25c772e2098114c16e56`；`unet_savedmodel.zip` 的 SHA-256 `50ab28bc09b09c8d78586eba442be27c8e98cbb45a3e07700a1e4b0ab733048d` 与发布 API 一致，ZIP 全部成员 CRC 校验通过。

作者的 `inference.py` 将单张图片转为 3 通道 RGB、缩放到 256×256，读取输出键 `conv2d_transpose_1`；但 SavedModel 的 `serving_default` 签名输入为 `[N, 256, 256, 6]`，输出键为 `output_0`。静态检查后，在独立环境用合成的 3 通道输入按示例调用，实际报出输入通道 3 与卷积核通道 6 不匹配。没有对该模型做真实影像推理或精度判断；额外 3 个通道的含义和权重许可均未确认，也没有填充或伪造缺失数据。

### 直接识别淹水道路的研究方案

[FADS-Fusion 论文](https://www.mdpi.com/2072-4292/18/5/714)描述了以单张灾后 RGB 图片为输入的 YOLOv8 分支，可输出淹水与未淹水道路等类别。其[源码](https://github.com/vtnsi/FADS-Fusion)快照修订 `0142c4154b2c09b721a836f5feca96178a643401` 的说明要求先训练再整理权重；当前源码快照中没有已跟踪的模型权重，未找到可直接下载的作者训练完成权重。因此没有运行或接入此模型；未找到不等于证明任何其他地方都没有权重。

此外，该快照中单模型测试的 `LitYOLO.step()` 将 `preimg` 传入预测，而单图灾后配置声明 `pre: False`；融合接口的 `predict_belief()` 则使用 `postimg`。这只是源码层面的待核查差异，不能据此推断论文实际实验结果，若未来取得权重需先复现并确认正确输入。该方案现有推理包装还包含 CUDA 设备指定，现有服务器 CPU 及内存门槛尚未验证。
