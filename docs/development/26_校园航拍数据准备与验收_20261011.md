## 首次航拍素材登记

把原始视频放在数据目录的 `raw/` 下，再新建 `flight-manifest.json`。清单里的视频路径相对于 `--dataset-root`；每个原始视频登记为一个独立航次。`captured_at` 必须带时区；同时记录 `capture_time_source`（`dji_srt`、`manual` 或 `unknown`）和 `capture_timezone`。DJI SRT 没有时区，使用字幕时间时必须核对拍摄设备时区；旧清单可省略这两个字段，程序会明确标成 `unknown`。`sidecars` 没有字幕或飞行日志时填空数组。示例如下，视频文件名、拍摄地点和时间需要替换成实际值：

在 Windows PowerShell 中先检查路径、时间、分组和原片哈希，不会解码视频或写入文件：

```powershell
python scripts/vision/prepare_campus_water_data.py `
  --dataset-root D:\LuoJiaExperimentData\WHUWalker_vision_research\campus-water `
  --manifest D:\LuoJiaExperimentData\WHUWalker_vision_research\campus-water\flight-manifest.json `
  --output-dir D:\LuoJiaExperimentData\WHUWalker_vision_research\campus-water\annotation-pack `
  --dry-run
```

预检通过后，去掉 `--dry-run` 才会完整解码并生成抽帧和标注模板。原片、清单、抽帧、掩膜和评测报告都保存在研究数据目录，不放进 Git 或生产服务器。

`masks/` 初始为空。标注人员必须保存与原图同尺寸的灰度 PNG，0 表示非水体、255 表示确认的可见水体；同时填写归一化道路多边形。阴影、湿路反光、湖面和不确定区域不能猜成道路积水。

`detection-test-template.json` 只包含测试航次的抽帧，用于人车框标注。先删去不准备标注的冗余相邻帧，再在保留帧的 `objects` 中填写 `pedestrian`、`vehicle` 或 `ignore` 和像素框 `[x1,y1,x2,y2]`。真正没有目标的人工确认帧可以保留空数组；尚未检查的空数组不能当作负样本。车辆统一按路线感知所需的 vehicle 组评测，不把车型细分准确率混入本阶段结论。

同一份检测清单可分别评测 `whole_frame` 和 `road_roi_tiled`。后者必须在每帧的 `observation_regions` 标注 `vehicle_lane`、`pedestrian` 或 `road_surface` 等 ROI，每个区域需要唯一 `id`、`kind` 和 0–1 归一化 `polygon`；所有参与计分的人车框必须完整落在至少一个 ROI 裁剪范围内，不满足时评测器会拒绝该样本，避免把 ROI 外目标误算成漏检。两种推理口径应使用同一批图像、同一人工框和同一冻结阈值，再比较逐类指标和运行耗时。Songdo 全量结果仍是 whole-frame 外域基线，不能代替此项校园道路 ROI 比较。

`event-test-template.json` 为每个测试航次保留原视频路径、来源哈希、地点和拍摄时间，并把镜头稳定性、已检查事件类型、观察区域和事件时间段留作待填字段。完成逐段人工检查后删除 `annotation_pending`；运行统一事件评测时，`--manifest` 指向该模板的已标注副本，`--dataset-root` 指向原始航拍数据目录。

## 验收边界

这套工具证明的是数据来源可追溯、视频覆盖完整以及训练/测试隔离。它不证明模型已经识别武大积水或准确检出校园人车，更不能直接发布路况。只有独立测试航次完成人车框、道路 ROI 和事件标注并达到相应指标后，才讨论启用可选模型；所有候选仍须管理员复核。

当前专项测试覆盖清单分组、路径越界、路径重复、内容哈希重复、时间地点元数据、地点跨集合泄漏、原片哈希、视频提前截断、抽帧时间戳、模板隔离、拒绝覆盖和命令行只读预检。

同一批完整原片还会生成待标注的 `campus_event_detection` 清单，用于车辆拥堵、人流拥挤、事故和积水的事件级评测。事件清单保留完整视频，不拿相邻帧充当独立样本；每段测试视频明确声明已人工检查的事件类型、观察区域和起止时间。执行入口、区域类型约束和示例见 [`22_无人机专用模型接入与评测.md`](22_无人机专用模型接入与评测.md#校园多事件统一评测)。

## 一键就绪审计

`audit_campus_field_readiness.py` 汇总航次清单、人车人工测试标注、事件人工测试标注、权重文件和评测报告。报告会核对清单与报告 SHA-256、测试航次分组和权重来源；权重文件存在只显示为 `present`，不会据此判模型有效。它不运行推理。

事件报告还必须为每种声明的事件类型提供按独立测试航次计算的置信区间，并覆盖至少 3 个已人工检查该类型的独立测试航次；逐视频的匹配、漏检和误报编号须与人工事件清单及 TP/FP/FN 数量一致。道路可见水体报告必须带航次聚类 IoU 区间，逐图诊断汇总值须与逐航次的计数、正负样本及误报状态相符。审计会拒绝字段缺失或互相矛盾的报告。它只检查报告结构和内部一致性，不会重新运行模型，也不能代替人工检查原始标注。

## Songdo Vision v2 人车框全量外域评测

新增 `scripts/vision/evaluate_songdo_vision.py`，直接读取本地 `test.zip`，不解压 3.2 GB 影像包。评测先核对 COCO 类别、图像成员、图像尺寸和标注框，再用当前 `visdrone-rtdetrv4-s` ONNX 权重对完整官方测试划分逐图推理，并按类别和 IoU=0.5 做一对一框匹配。默认置信度阈值为现行 `0.369`；车辆检测器的 `van` 记入 Songdo 的 `car`，`motor` 记入 `motorcycle`。其他非目标类别不计入四类车辆分数，排除数量单独记录。

2026-10-11 全量运行命令：

```powershell
python scripts/vision/evaluate_songdo_vision.py `
  --archive D:\LuoJiaExperimentData\G1\01_raw\detection\songdo_vision\test.zip `
  --model D:\LuoJiaModels\visdrone-rtdetrv4-s.onnx `
  --confidence 0.369 --iou 0.5 --cpu-threads 4 `
  --output D:\LuoJiaExperimentData\G1\05_reports\songdo_vision_v2_detector_eval_20261011.json
```

全量覆盖 **1,084/1,084 张图像、55,528 个标注框**，没有漏读图像；CPU 推理均值为 0.4232 秒/张，全命令约 532.84 秒。微平均 precision=`0.7296`、recall=`0.9054`、F1=`0.8080`。分类型结果如下：

该结果暴露了车型间明显差异，特别是摩托车和卡车误检、漏检较多；不能把微平均分数当作各种车辆都可靠。此报告是一个固定置信度/IoU 操作点的框级评测，不是 COCO mAP、拥堵事件指标或校园精度。Songdo Vision 测试图像按图像随机划分而非独立航次；其 v2 部分标注由与本检测器同系列的模型辅助提出后人工确认，可能给相关模型带来轻微有利偏差。数据许可为 CC BY 4.0，须引用 Fonod 等人 2025 年论文（DOI `10.1016/j.trc.2025.105205`）。

**推理口径：本次只测了整幅画面的全图缩放路径，没有测管理端道路 ROI 切片路径。** 模型输入为 640×640；对 3840×2160 全图，内容缩为 640×360 后补边。COCO 标注的各类中位框宽、高（分别取中位数）约为：汽车 85×43 px、公交 157×57 px、摩托车 30×37 px、卡车 101×51 px；全图缩放后中位框高约 7、10、6、9 个输入像素。摩托车全图结果受小目标缩放影响的可能性很高，但当前数字不能量化 ROI 切片能提升多少，也不能把整图分数代替管理端道路 ROI 的实际精度。下一步应在画面上标注道路区域后，对同一批独立样本比较全图和生产切片推理的逐类指标、漏检与耗时。
