# 对话框架复核与验收（2026-11-07）

## 范围与结论

本次在发布工作区复核消息提交、完整上下文、任务绑定、模型与工具循环、候选和路线交付、失败恢复、旧客户端兼容以及 App 会话。下面的检查支持代码、隔离数据库、浏览器模拟和小规模真实服务联调通过；真机生命周期、真实定位与现场道路情况仍未验收。论文实验与历史诊断记录不在本次清理范围。

## 发现和修正

1. 平坦路线的历史状态会保存 `slope=prefer`，任务状态的硬约束却不接受该字段。跨话题恢复路线时模型曾两次收到状态校验错误，随后新建任务，丢失原搜索中心。现在恢复时将路线偏好和硬约束转换为一致的任务状态，并保留原搜索中心、范围、所选地点和已有硬约束。
2. 普通路线偏好可能把已有的避坡或避台阶条件改成 false。现在偏好变化保留已有硬约束；用户明确取消时，模型通过 `clear_fields` 指定对应约束字段，其他条件继续保留。
3. 指定数值扩圈时，已展示地点的记录可能被清空；更换起点时，依赖旧起点的候选可能继续复用。现在单纯扩大同一搜索范围会保留已展示 ID，更换起点、出行方式或影响检索的硬约束会使旧候选失效。
4. 天气、路况工具故障后，模型即使说无法查询，运行仍可能被当作成功。现在将未恢复的服务故障记录为失败或部分完成，保留已经核验的结果并提供重试；重复故障保留实际服务原因。浏览器复测了部分结果与重试操作。
5. 旧 `/api/chat` 在模型模式遇到规划异常时仍会进入规则解析；`/api/chat` 和 `/api/parse` 还会静默截断超过 500 字的输入。模型模式现在返回可重试的服务错误；两接口拒绝超长输入并说明上限。

前端仍限制单条输入 200 字，新会话消息接口限制 500 字；完整上下文指传入所有已接受的消息原文，仍受模型总输入上限约束。旧 `/api/chat` 和 `/api/parse` 是无持久会话的兼容接口，不能承诺自动恢复完整对话；新版界面使用会话消息与运行轮询接口。

## 清理与保留

删除新对话实现中已无调用者的旧任务类型与工具白名单、自动拼接网页检索词函数、过时的工具开关参数和只写不读状态。保留显式旧模式、旧接口与测试所依赖的规则实现和数据库兼容路径；它们不是当前默认模型路径。`legacy/` 是已有记录的历史部署档案，实验冻结文件、旧数据库记录、构建工具和桌面旧工作区均未删除。
