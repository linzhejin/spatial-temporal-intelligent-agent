# 影像改动复核与验收

验收日期：2026-11-08 至 2026-11-09（北京时间）。结论：**基础上传、持久化与原有人工复核流程的相关检查通过；新增影像道路建议不能整体验收通过。** 以下问题均保留了复现证据。本轮没有修改运行代码、生产数据、部署配置或模型开关。

- 新内容包括 DJI SRT 姿态解析、`camera_pose` 持久化及迁移 017、像素配准原语、掩膜/拍摄范围/邻近半径三级道路建议、管理台复核交互，以及少量用户端地图和文案修正。
- 生产三个服务为 active，健康接口为 ok；只读查询确认 `camera_pose` 为 JSONB。公网管理端脚本、用户端脚本、管理端样式及 Service Worker 均为 HTTP 200，内容与受检提交一致。

## 架构评估

姿态数据从浏览器经分块上传元数据写入任务，服务端读取任务后生成道路建议；发布仍经过候选复核、道路确认、现场依据和时效校验。这些边界基本保留，数据库扩展也兼容未提供姿态的旧客户端。

但当前“掩膜投影”只调用 `pose_to_homography_init`，没有调用新增的 `fit_pixel_to_gcj` 做道路对应点拟合，也没有使用配准残差作准入条件。它目前是姿态估计提供的参考，不能认定为已通过真实道路基准校准的影像定位。`vision/registration.py` 顶部“仅离线使用、不接 API”的说明与实际调用链不一致。

## 发现的问题

### R1 · P1 · 掩膜投影忽略俯仰角，可能推荐完全不同的道路

位置：`vision/registration.py:78`、`spatial/vision_suggest.py:237`。

`pose_to_homography_init` 只根据高度、焦距和偏航构建正下视变换，没有读取 `gb_pitch_deg`；接口却允许将任意姿态送入此变换，并把命中结果标为 `mask_projection`。

独立反例使用平坦地面、相机高度 100 米、俯仰 -45°、朝北、画面中心的积水轮廓。按光线与地面交点计算，中心应在机身以北 100 米；实际变换得到 `(0, 0)`，建议列表选中了机身正下方的道路，漏掉正确道路。该条件被现有参数解析接受。

处理要求：使用含俯仰的有效地面投影，或在未经验证的姿态下明确降级；缺失姿态、地面高度和相机内参不能默认为已校准。保留人工复核闸门。补充独立于实现公式的倾斜拍摄真值测试。

### R2 · P1 · 点击建议路段会清空已确认候选，导致无法发布

位置：`static/js/manager.js:2867` 至 `2870`；后端校验位于 `api/routes.py:2704`。

实际浏览器 → Flask → 独立 PostgreSQL 复现：确认候选 → 将此候选转入道路事件 → 点击建议路段 → 填写类型、处理方式、受影响方式与现场依据 → 确认道路 → 发布。

`pickSuggestedEdge` 调用 `clearVisionSource`，随后把 `sourceCandidateIndex` 固定设为 `null`。页面显示“信息已齐全，可以发布”，但请求携带空候选编号，后端返回 HTTP 409 / `vision_candidate_ambiguous`。数据库中的候选 0 已经单独确认，旧版整任务 `review_status` 为空，因此旧兼容逻辑不能恢复它。

处理要求：同一任务选路时保留明确且已确认的候选关系；未选择候选时先引导选择，并在前端阻止发布。多候选任务不能默认取第一项，后端复核校验不能放宽。

### R3 · P2 · 拍摄范围的倾斜投影被简化为平移矩形

位置：`spatial/vision_footprint.py:159` 至 `170`。

当前只平移正下视矩形的中心，宽高不随俯仰改变。反例同为高度 100 米、俯仰 -45°，图像 1000×500、35mm 等效焦距 24mm。针孔模型下，画面竖向中心线覆盖北向约 45.45–220 米；程序给出 62.5–137.5 米，将实际在视野内、北向 200 米处的道路排除。

这是 L1 回退本身的问题，修复 L2 或关闭积水模型不能消除。应由各角光线与地面相交得到范围，并对越过地平线、缺少地面高度等条件降级，或严格限制到已验证的近正下视范围。

### R4 · P2 · 视频和姿态无法对时后仍标为掩膜投影

位置：`spatial/vision_suggest.py:117` 至 `129`、`237`。

掩膜时间不在姿态轨迹范围时，`_pick_pose` 改取距离参考点最近的轨迹位置，L2 仍继续执行。受控样例中只有第 0 秒姿态、轮廓来自第 100 秒，输出依旧是 `mask_projection`。这时没有证据说明两者属于同一拍摄位置。

处理要求：设置明确的时间匹配容差；无法对时则退出帧级掩膜投影，降低建议依据等级。现有 `test_mask_time_out_of_range_falls_back_to_nearest_pose` 反而断言此时仍为 L2，需要修改测试所保护的行为。

### R5 · P2 · 重新吸附会让路口附近的有效建议失效

位置：`static/js/manager.js:2905`、`1345`；`spatial/road_conditions.py:956` 附近的建议吸附点输出。

建议已经包含具体边 ID，但点击后只用经纬度再次寻找最近道路。参考点投影落在端点/路口时，多条边距离相同或极近，第二次搜索可能选中另一条边。前端严格比较边和几何，随后清空道路，要求重选。

使用正式路网的确定性节点样例共比较 40 个建议，17 个重新吸附后身份不一致。该取样专门涉及节点附近，**不能作为全校园发生率**；它证明现有“点击建议”测试只验证发出了吸附请求，没有验证建议能保留到发布。

处理要求：把建议的具体边身份用于服务端复核与绑定，保留方向、几何和当前路网校验，避免仅用一个路口坐标重新猜测目标边。

### R6 · P2 · 续传身份没有包含相机姿态，会沿用旧字幕数据

位置：`static/js/manager.js:1924` 至 `1931`、`1967` 至 `1975`。

续传只比较视频、拍摄时间、参考点、观察区域和场景，没有比较 `cameraPose`。首次上传中断后，用户更正同名字幕或补充姿态，只要其他条件不变，程序仍复用旧上传会话；新姿态只在创建上传会话时发送。

直接执行当前上传函数的受控复现中，旧姿态高度为 50 米，新字幕为 100 米，续传没有创建新会话，完成结果仍携带旧的 50 米姿态。后端完成上传确实读取旧会话元数据，因此这不是单纯的界面显示差异。

处理要求：将标准化姿态的摘要纳入续传身份，变更时新建会话或经过显式版本校验更新元数据；同时覆盖新增、更换、删除字幕的场景。
