## 5. 项目现在是什么、做到哪里

**定位：面向校园出行与运行管理的时空智能体。** 用户用自然语言描述需求，系统把地点、距离、道路通行、时间、个人偏好和已确认路况组合成可执行的出行方案。航拍提供带时间、位置和证据的观察，经管理员确认后进入同一套空间决策。

当前属于**核心产品已上线、研究验证和无人机高级识别继续完善**的阶段。功能完成度按模块列，不用一个无法复核的“总完成百分比”。

| 模块 | 已有实现及本次依据 | 主要剩余工作 |
|---|---|---|
| 自然语言 Agent | LangGraph 编排；14 个工具；结构化路线/地点需求、多轮澄清、PostgreSQL 状态和后台任务 | 用冻结的独立任务集验证长对话、组合任务和失败恢复，不能仅沿用修复问题时使用的题目 |
| 地点推荐 | 正式 POI **443** 个，含校门 **17** 个；餐饮 128、运动 28；活动用途检索、路网距离排序与常用别名已进入代码 | 已有用途不代表所有设施开放/可用；新增设施和条件继续留依据。443 条中 180 条有非空用途字段，其余包括宿舍、校门等，不机械填满运动/餐饮用途 |
| 路线与用户体验 | 步行/骑行/驾车、多途经点、游览、偏好重算；PC 手选起点，手机定位/导航；Android WebView 壳 | 代表性跨学部/校门路线与真实用户体验仍需抽查；不要求逐条测完几千条道路 |
| 地理数据 | OSM＋校方课程数据构成可计算路网，高德用于底图/地点服务；本机路网 **5,087 节点、14,622 条有向边** | 路网属性和坐标/接驳疑点继续核对；覆盖率、占位字段和成功算路不能证明现场全部可通行 |

## 7. 后续主线与论文定位

建议把论文候选问题收敛为：**带结构化任务记忆与时空事件约束的校园出行智能体，能否更稳定地理解多轮需求、调用空间工具并完成合理的动态出行决策。** 这是待实验验证的研究问题，不是已经证明的创新结论。

按以下顺序继续：

1. **统一工作基线。** 以后生产功能修改以 `9c7cb92` 或其后继发布版为基线；单独保存桌面 OGE 等在研改动，避免从旧目录反复开发和覆盖新能力。
2. **完成 Agent 独立对照。** 固定任务、数据和模型设置，对比完整系统、无结构化记忆、受限空间工具等配置；重点测需求保持、目的地正确、约束满足、失败恢复与耗时。既有 C1 为开发预实验，不能直接当最终论文成绩。
3. **选少量关键场景核实。** 优先校门、跨学部连接和明确用户需求的代表路线；不把全校逐边测绘设为主实验前置条件。
4. **航拍先做试点闭环。** 少量稳定道路视频配合人工道路区域、人车和事件标注，比较整幅画面统计与“道路区域＋跟踪＋复核”方案；事故正例可用合适的公开视频，校园正常航次用于误报检查。
5. **补足事故与积水后再扩展论文主张。** 当前可客观描述接入和验收机制；要写具体识别效果，必须有对应独立实验。视觉模块的困难不应阻止 Agent 主线对照先开展。

最终是否适合《测绘学报》专刊，应由导师结合征稿范围、研究贡献与独立实验判断。现在适合向导师展示可运行的系统和上述研究问题，不宜声称全校道路或四类航拍识别均已验证。
