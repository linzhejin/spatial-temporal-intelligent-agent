# 公开积水权重与道路组合复核

日期：2026-11-12。续 76 至 78 号记录，原始失败与限制记录保持不变。

## 结论

又实际运行了三份公开积水权重，并将其中两种输出与已有三份自动道路结果组合。**本轮没有发现可以支持开放免圈选候选的方案。** 直接使用的新模型仍会把大量非道路区域作为候选；加道路模型后，部分组合漏掉大量已标注的积水道路。样本已经用于多轮筛查，不能作为独立测试或校园现场精度结论。

本次未训练模型、使用付费计算或修改生产。免圈选原型保持关闭，事故模型不在本轮启用范围；此前可用的人工圈选及人工复核流程不因这次试验改变。

## 共同方法和统计范围

沿用四张 Ian 示例和 16 张 Delta 筛查图片；其中 Delta 的 8 张有淹水道路标注，8 张没有。输入来自此前留存的 512×512 RGB 图片；模型推理不读取标签，待预测保存后再对照道路和积水标注。使用原型的连通域和多边形生成逻辑，最多输出 24 个候选；栅格化及轮廓简化会带来误差。多边形空洞不完整的候选从面积统计中排除并记录数量，不能把剩余面积当作完整结果。

下表的「有交集」仅表示至少一个候选像素落在积水道路标注中，不能等同于成功检出完整路段。「无标注图有候选」指没有淹水道路标注的图片产生了候选，并不证明图内完全没有洪水。道路标注以外也不一定意味着现实中没有道路。候选像素中的标注外比例和已标注积水道路覆盖率均为本批样本的像素汇总，不能外推为项目准确率。

道路模型、权重哈希及预处理限制见 76 号记录：SatLens 使用发布的处理器；UPerNet / Swin 权重许可和预处理未确认；SpaceNet 5 仅用单折且未与作者原环境对齐。三者均未用于产品发布。

## Doodleverse v4 与 v10

从 [Doodleverse FloodNet 模型发布页](https://zenodo.org/records/7566797)下载 v4 和 v10 的 H5 完整模型，下载文件分别与发布方 MD5 `360ed98d2403fb55d4e99544b19fa19c` 和 `57884ecd2a3aff2b7f9a58e3b5fc2fa6` 一致。记录的 SHA-256 分别为：

- v4：`747bc5e1ff1a45745359990db8511ce6f04b5348ca2eadd394e71625b9bc958f`。
- v10：`6194edc89310ae1eb5d190b4130f2008ef404bedb5744d435475849f6f1608d2`。

发布记录标明 CC-BY-4.0；训练数据及实际使用条件仍需分别核对。在 TensorFlow 2.10.1 CPU 环境按既有 Doodleverse 输入处理进行单张 768×1024 RGB 推理，并检查输入、输出类别和数值范围。只在四张既用示例上做筛查，没有运行独立测试或 Linux 资源验收。

用户展示图 `HURRICANE-IAN_000491` 共有 16,879 个标注淹水道路像素。v4 达到 24 个候选上限，候选覆盖其中 7,531 个像素；63,487 个候选像素中有 55,939 个位于道路标注外，约 **88.11%**。v4 和 SatLens 道路直接相交后只剩 1 个候选、6 个像素。另一张没有淹水道路标注的 Ian 对照图上，v4 仍产生 8 个候选。

v10 在展示图同样达到 24 个候选上限，其中 5 个候选的空洞无法完整表示，评分程序按约定排除这 5 个，故本次不能报告完整候选面积或覆盖率。该现象是原型表示能力的限制，不应归因于模型本身。v4、v10 与既有 v6 的投票探索及逐图结果亦保留在结果文件中，没有据此切换生产模型。

## 现有 v7 与自动道路组合

重新运行现有 Doodleverse v7 ONNX，取得模型输出的淹水道路类别并与既有自动道路掩膜直接相交。16 张 Delta 结果如下：

| 筛查组合 | 8 张有标注图至少有一像素相交 | 8 张无标注图有候选 | 已标注积水道路像素覆盖率 | 候选像素位于道路标注外 |
| --- | ---: | ---: | ---: | ---: |
| v7 直接候选 | 3 | 8 | 约 4.73% | 约 93.57% |
| v7 与 SatLens 道路相交 | 2 | 3 | 约 0.48% | 约 25.00% |
| v7 与 UPerNet / Swin 道路相交 | 3 | 4 | 约 3.83% | 约 38.73% |
| v7 与 SpaceNet 5 道路相交 | 1 | 3 | 约 0.02% | 约 20.89% |

这些组合在本批图片中减少了非道路候选，但积水道路覆盖率仍低。展示图上，v7 与 SatLens 相交产生 15 个候选，覆盖 1,274 / 16,879 个标注淹水道路像素，1,615 / 5,352 个候选像素位于道路标注外；与 UPerNet / Swin 相交产生 8 个候选，分别为 4,738 / 16,879 和 1,973 / 9,532。该组全部用于筛查，不应凭单张图的改善判定方案通过。

首次尝试用模型研究环境生成 v7 输出时，因缺少 `skimage` 在推理前失败，未产出结果；随后改用已有本机环境完成输出，失败目录保留。运行时对现有 ONNX 节点有兼容性警告；此处没有重新证明原 H5 与 ONNX 的数值对齐。

## 新增水域 ONNX 与自动道路组合

[Disaster-Response 作者源码](https://github.com/YMP7/Disaster-Response)固定快照 `92ae9151d258322bc42e55502f8d988dee66adb4` 中包含 `stage2_flood_unet_v2.onnx`，SHA-256 `d91afb9c5be14a820debb6974d88708a5cb7b480d885f4050423cd6b9527f180`，与该快照自带清单一致。源码将洪水标签定义为 FloodNet 的**水体或淹水道路**，故输出不是单独的道路积水类别；README 描述了训练和精度，但不能仅凭它确认权重的完整训练来源。仓库快照中未见 README 链接的 LICENSE 文件；代码、权重和数据的实际使用条件均未确认，不能直接部署。

按照作者 ONNX 接口，以单张 RGB 缩放至 128×128，进行 ImageNet 标准化、logit 大于 0 二值化，再按最近邻放回 512×512；用 ONNX Runtime 1.20.1 CPU 保存预测。随后与既有道路掩膜相交，并调用原型轮廓生成器；这里向生成器传入的是二值图，只用于比较几何，不表示模型置信度。

| 筛查组合 | 8 张有标注图至少有一像素相交 | 8 张无标注图有候选 | 已标注积水道路像素覆盖率 | 候选像素位于道路标注外 |
| --- | ---: | ---: | ---: | ---: |
| 水域输出直接生成候选 | 7 | 8 | 约 34.82% | 约 96.29% |
| 水域与 SatLens 道路相交 | 3 | 8 | 约 3.22% | 约 30.67% |
| 水域与 UPerNet / Swin 道路相交 | 5 | 8 | 约 9.92% | 约 33.90% |
| 水域与 SpaceNet 5 道路相交 | 1 | 5 | 约 0.32% | 约 22.59% |

该水域模型在展示图上直接产生 8 个候选，74,182 个候选像素中 65,630 个位于道路标注外；与 SatLens 相交后剩 3 个很小的候选，与已标注淹水道路没有像素交集。这些结果不足以判断作者原模型在其训练分布内的性能，但不支持把当前组合接入本产品。
