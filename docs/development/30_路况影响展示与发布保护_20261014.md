# 路况影响展示与发布保护（2026-10-14）

## 问题

路况页面曾按“施工、事故、积水”等事件类型推断路线影响，没有采用记录中的 `action` 和 `affected_modes`。因此管理员发布“仅提示”或只影响某种出行方式的事件时，图例和弹窗仍可能把它说成封路或缓行。旧的路况表单也没有发送影响设置，服务端会按兼容默认值把三种方式全部设为禁行。

## 修复

- 新记录的地图图例、路段样式及信息窗优先读取实际 `action`、`affected_modes` 和 `cost_multiplier`。提示、缓行、封路及未受影响方式会分别显示；只有确实影响当前出行方式时，才显示禁行或增加规划成本。
- 管理员旧路况表单现在要求选择“仅提示、允许通行并增加成本、禁止通行”之一，并至少勾选一种出行方式。缓行额外校验 1–5 倍成本；吸附道路时仅在影响设置完整后生成路线影响预览。提交反馈按实际动作说明，不再一律说“路线自动绕行”。
- 新 API 请求缺少明确动作与适用方式时拒绝发布。兼容旧格式时，只有显式提供 `blocked_modes` 才接受封路记录；不再替调用方默认封闭全部方式。航拍事件继续要求明确动作与适用方式。
- 没有动作字段的历史记录保留原有按类型解释方式；带明确 `blocked_modes` 的旧记录按已记录方式显示。
- PWA 缓存升至 `whu-walker-v90`，首页的 JS/CSS 查询版本同步更新。
