# Agent 产品发布候选与验收（2026-10-25）

## 范围与决定

从 `main` 提取用户可感知的修复，形成 `codex/agent-release-candidate`。研究分支的模型用量探针、固定天气注入、实验脚本、已见题和运行证据不进入本候选。桌面主工作区的未提交材料未被修改。

候选包含：明确地点缺起点时保留目的地并追问起点；只有明确起点时追问目的地并保留策略；多阶段活动在选择候选后继续后续地点；防止“刚才的起点”被当作新地点；复合天气与路况请求反馈实际取得的信息；开放式活动途经点不被误识别为具名地点；三处集贸市场 POI 的学部字段修正。修改集中在 `agents/planner.py`、`agents/task_planner.py`、`agents/tools.py`、`api/routes.py`、`spatial/poi_taxonomy.py`、`data/pois.json`，并附对应回归测试。

## 未过的发布闸门

1. 为候选版提供显式隔离的 PostgreSQL，并复跑 API／worker／旧会话兼容与动态路况集成测试。目前 `TEST_DATABASE_URL` 未配置，不得把跳过计为通过。
2. 在 PC、手机网页及既有 Android 壳上使用真实后端完成澄清、候选选择、按顺序的全程路线、天气追问、路况重算和刷新续接；覆盖超时、取消、重试。
3. 核对生产环境配置与回退步骤，再合并到受管理的 `main`、同步两处远端并部署。部署前后记录提交、数据哈希、服务状态和代表请求；线上复查用户端与 Android 壳实际访问到新版本。

本候选不是已合并版本，也不是已部署版本。论文正式对照实验与道路现场真实性仍按各自证据另行判定。
