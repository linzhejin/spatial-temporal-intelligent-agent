# 研究分支产品改动的整合与发布闸门

> 2026-10-25 决策与验收工作单。基线 `main` 为 `6d78bc5`，研究分支 `codex/isolation-cleanup` 为 `34bc00e`。提交号在后续推进时须重新核对。本页不表示已经合并或部署。

## 决策

研究分支比主线多 170 个文件，包含实验脚本、已见题、运行证据和论文材料。不能把整支分支当作一次产品更新发布。桌面主目录还有用户未提交的文档和研究材料，整合时不得覆盖或顺手提交。

产品发布候选只讨论 `agents/planner.py`、`agents/task_planner.py`、`agents/tools.py`、`agents/workflow.py`、`api/routes.py`、`spatial/poi_taxonomy.py` 和 `data/pois.json` 中与用户任务有关的改动。即使在这七个文件里，模型用量记录、固定天气输入和研究探针接口也要逐段判断用途，不能按文件整包合入。

## 按顺序执行

1. **拆分改动。** 以当前生产 `main` 为基线，在隔离工作区按行为选择多轮任务状态、明确起终点、候选选择、途经点顺序、策略与天气追问等产品修复；研究专用接口另留研究分支。形成逐项来源清单和可审查差异。
2. **本地验收。** 针对被选入的行为运行相关单元和 API 检查；实际操作 PC、手机网页和 Android 壳中的澄清按钮、候选选择、多途经路线、路况重算、刷新续接，以及超时、取消和重试。每项保存输入、结果和失败原因。`tests` 通过只证明对应范围，不代替端侧或线上验收。
3. **数据与路网边界。** 两条集贸市场学部标签修正需核对 POI ID、坐标、类别、重复名及检索结果。图内审计检查边序、方向、连通、方式和途经顺序；现场能否走仍标记为未知。`check_deployment_readiness.py` 是全校园数据现场核实闸门，会对大量尚无现场证据的条目报阻碍；不能把它的全量通过误设为本次 Agent 修复发布的前提，也不能把产品回归通过写成全校道路已验证。
4. **合并与部署。** 发布候选的本地回归、端侧交互、生产配置兼容及回退方案通过后，再合入受管理的主线，同步 GitHub/Gitee，并按现有腾讯云流程更新 Web 与 Agent worker。记录部署前后提交、数据哈希、服务状态和代表请求。若改动未通过，先修复再重复对应验收，不发布半成品。
5. **线上复核。** 核对用户网页与 Android 壳均请求到新服务，检查真实模型的多轮追问、双途经点全程路线、天气与原路线共存、路况重算；确认旧会话兼容和生产事件未被实验数据污染。失败时按部署前快照回退，并保存故障记录。

## 分开的两种结论

- **产品发布可行性：**由被选入的代码、端侧交互、服务配置和线上观察决定；当前尚未完成此页验收。
- **论文正式实验就绪：**由未见测试集、独立答案、三架构公平对照和预算等门槛决定。当前拆分报告为 `formal_ready=false`；产品修复上线不能改变这一结论。
