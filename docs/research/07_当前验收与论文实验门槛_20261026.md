# 珞珈智行：当前验收与论文实验门槛（2026-10-26）

本页只记录本轮重新运行或线上观察到的证据。历史过程见 [项目完善与正式实验执行方案](06_项目完善与正式实验执行方案_20261016.md)，产品发布记录见 [Agent 产品验收](../development/34_Agent产品发布候选与验收_20261025.md)。

## 已能演示的产品链路

- 用户页和管理页已在腾讯云运行。手机尺寸浏览器的真实线上请求“从星湖园食堂到卓尔体育馆，避开台阶”返回约 1029 m 的步行路线；刷新前后路线面板与地图折线均可见。刷新恢复只接受与当前路网数据、路况版本一致的已完成路线。
- PC 浏览器已实际完成“从信息学部出发，先打篮球，再到星湖园食堂”：先给出三个篮球场候选，选定信息学部篮球场后给出到食堂的全程路线。此为功能样例，不是任务成功率或现场可通行性证据。
- 本轮数据结构校验统计 443 个 POI、17 个校门、5087 个节点及 14622 条有向边，必填字段、坐标范围、类型、别名冲突及校区归属错误均为 0。`poi_387`、`poi_388` 是工学部集贸市场内的餐饮点，与已核对的市场主体 `poi_415` 位置相邻，补用了同一工学部边界依据，消除了旧重叠多边形造成的两条误报。12 米内的 101 对邻近点只是复核线索，不等于 101 对重复实体。

## 接着推进

1. 当前 POI 边界依据已随提交 `1051f59` 同步到 GitHub、Gitee 的 `main` 并部署腾讯云；三个服务均为 `active`，线上健康检查正常。对应提交仍需生成实验输入清单，且开发清单不能冒充正式冻结快照。
2. 用开发集检查正式任务链和工具轨迹，优先定位可绕行题的 Agent 超时波动，并回归无可行路的保守回答；同时准备不与开发题重叠的盲测候选。测试题一旦被用于修复，就标记为已见，不再计入未见盲测。
3. 同一底模先比较普通工具 Agent、DeepSeek Harness 与珞珈智行；再按预算扩展 Kimi、GLM 等模型。分别报告完整任务成功、硬约束违规、延迟与费用，不把解析基线误写成完整系统对照。
4. 用公开影像建立“画面事件→模拟道路关联→管理员复核→路况生效→智能体重算”的开发案例。模型识别效果、道路关联和路线影响分开评分，模拟位置不得写成真实航拍定位。

目前不需要用户逐条核查全校道路。程序先整理小批歧义题与影像案例，只有必须由人判断的地点含义、影像道路对应和付费预算再集中请用户确认。

“300 题逐题人工裁决”的旧门槛与最小人工投入目标存在冲突；新的[混合判分与最小人工审查方案](09_正式实验混合判分与最小人工审查方案_20261026.md)先限定可自动核验的受控任务，再另报自然表达和代表路线的人工审查。新版协议和独立判分器尚未实现，现有正式门继续关闭。
