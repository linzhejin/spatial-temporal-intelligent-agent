# 珞珈智行论文实验：执行与验收清单

> 2026-10-25 制定。执行依据为桌面《珞珈智行_论文实验推进方案_最终执行版_20261023.docx》、`experiments/protocol_v2.json` 和 `11_按完成条件推进与证据看板_20261023.md`。本文件记录工作顺序和证据门槛；打勾须有对应的实际文件或运行结果。

**目标：**完成可复现的校园时空智能体对照、动态事件与公开影像模拟联动，并将经验证的结果写入论文。先完成开发态验收，再冻结正式输入；日期不是通过条件。

**现有结构：**用户与管理端仍用现有 Flask 服务；Agent、独立路网评分、DeepSeek Harness、普通工具 Agent 和视觉后台在独立实验环境运行。研究工作区为 `codex/isolation-cleanup`；生产主线只接收经过发布验收的产品修复。

## 共用验收规则

- 所有记录包含 Git 提交、POI/路网/道路层/事件/工具模式/模型配置哈希、运行命令、原始输出哈希、失败与未知原因。开发运行必须标记为开发态。
- T1–T5、O1、D1、V1、V2 分别记录分母、样本来源和结论边界。产品的“核验通过”、合成事件与公开视频模拟位置不能充当独立道路或影像真值。
- 使用同一模型比较三种 Agent 时，固定工具权限、数据、天气/路况输入、事件时钟和请求预算；模型响应身份、实际 HTTP 次数及费用均要留痕。任何一项缺失，该运行只能作开发诊断。
- 已经用于修复代码或调参的题目及同源场景族保留为已见材料，正式留出集必须另行封存。未能独立判定的地点接驳、通行与模糊语义记为未知，不补造通过结论。
- 实验仅写独立测试数据库；公开视频事件必须标记为模拟位置，不能发布到生产路况。

**P0 通过证据：**版本、输入和环境清单存在，隔离检查通过；正式冻结另需准备好的研究快照和干净 Git 提交。

## 2. P1：题目、来源和独立判分

- [ ] 保留 60 条开发题和 120 条多样化编题草稿的状态标签。用 `experiments/scenario_split_audit.py` 对实际起点、起终点、模板、原文与来源组重新审计；将结果写入独立报告。
- [ ] 将 16 张用户已裁决的歧义卡落实到 T3–T5 语义规则：7–9 读取同一未完成任务的明确目的地；13–15 在选点后输出有序全程。针对逐题其余不可自动裁决的情况保留证据与未知状态。
- [ ] `experiments/route_reference.py` 与 `experiments/candidate_reference.py` 依据冻结图和 POI 重新计算图内参考；对 T2 当前 11 条接驳或排序边界题逐项记录“不影响排序 / 需独立证据 / 未知”，不把估计末端距离当实测。
- [ ] 在代码和数据确定后另封存真正留出的测试集，完成来源裁决；正式评分要使用 `experiments/scenario_runner.py` 的快照、拆分和独立重算门槛。BFCL V4 的 40 题由官方评分器单独评价。

**P1 通过证据：**120 条正式题各有来源和可判答案或明确未知；开发与测试拆分审计 `formal_ready=true`；独立评分器对错误边、错用途、错误顺序及不可达反例给出相应判定。

## 3. P2：同模型三架构及扩展模型

- [ ] 先用 DeepSeek 对 T1–T5 各做多个同题开发运行，检查普通工具 Agent、固定提交的 Harness 与珞珈智行的工具定义、输入、回应内容、模型响应身份、实际请求数、超时和重试；共同天气与事件使用固定夹具。
- [ ] 用 `experiments/comparison_gate.py` 核对三条件运行清单；对每组测 token、时间及失败分布，计算批量费用区间，记录用户批准的费用上限后再批量调用。
- [ ] 接通 Kimi、GLM 后分别做同样的开发兼容性检查；无凭证、能力不匹配或预算不足时标为未运行，论文结论随实际完成矩阵缩小。
- [ ] 冻结后对 T1–T5 每题每条件运行计划的 3 次；在同一模型上完成任务记忆及结果核验消融，保留所有超时、无结果和未知。

**P2 通过证据：**九配置的实际可运行状态逐一有记录；主矩阵和消融的每个计划运行均入表，外部评分与按场景族配对统计可复算。开发试跑不充当论文成功率。

- [ ] D1 受控事件补齐封闭、方式差异、缓行策略、时效、撤销恢复、无关或无替代路径六类各 4 个。现有 24 条“封闭/到期”回放只作开发资产，不能代替六类样本。
- [ ] V1 保持 6 段独立 Songdo 视频与 12 个模拟校园道路关联，核对文件、时长、分析范围和来源；用真实模型输出生成候选，管理员逐项确认或排除，再检查受影响模式、路线、过期及恢复。无候选时如实记录，不人为补阳性。
- [ ] V2 保留 VisDrone 固定 100 图的检测与误差记录，报告 F1、召回、阈值及适用范围；不把人车检测当作拥堵或事故真值。影像抽查材料整理为 6–10 个可审短片和道路示意后再交用户。

**P3 通过证据：**D1 六类受控结果及失败均可复算；V1 至少 12 个模拟映射案例有模型输出、复核状态和事件/路线结果；无事件案例同样计入；V2 独立于动态事件报告。
