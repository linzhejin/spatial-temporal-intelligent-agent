# 复合路况与事件不可达开发题实施计划

**状态：开发题方案，尚未形成模型成绩。** 本增量承接 `09_正式实验混合判分与最小人工审查方案_20261026.md`。只构造可复现的模拟路况，验证“查路况＋规划路线”和“事件导致不可达”的完整任务链；不宣称武大现场确有封闭。

## 冻结输入与预设案例

- 使用现有 `data/whu_road_network.graphml`、`data/pois.json`、`experiments/datasets/controlled_spatial_v1/` 的边界和步行锚点。受控图为 WGS-84；POI 到路网的最后一段接驳仍未现场核验。
- 新建专用的模拟事件快照，标记 `scope=synthetic_development_only`、`campus_truth=false`，为每个事件保存精确 `(u,v,key)`、受影响方式、起止和评测时刻。快照不得写入生产数据库。`active_closed_edges` 必须按时间、方式和精确边身份解析，拒绝引用不存在的边。
- 案例 A：`poi_001 → poi_015` 步行，模拟封闭边 `(13266196548,13266196543,0)`。独立图诊断中原路线为 521.8 米，封闭后仍有约 575.413 米的替代路线。题目要求先查路况，再给出受封闭影响后的**全程**最短路线；金标准包含 `road_events` 与 `route` 两项输出、具体边序列和冻结图内距离。
- 案例 B：相同起终点，模拟封闭边 `(13273047778,13273047777,0)`。独立图诊断显示在当前步行准入图上无路，且该准入图未知边数量为 0。题目要求查路况并判断是否能走；金标准为 `no_route`、无路线边序列以及不可达解释。若源图变化导致这两个诊断不再成立，生成器必须报错，不能沿用旧答案。

这两个事件都是**人为构造的受控输入**，不是影像识别结果、真实管制或校园通行真值。事件案例只能检验冻结图中的决策行为。

## 实施与验收顺序

1. **事件来源与案例生成。** 为模拟事件快照、题目模板、图与锚点建独立来源清单；加入 LF 文件规则，避免 Windows 检出改变原始字节哈希。生成器仅从冻结输入构题，`event_infeasible` 必须包含 `frozen_event_snapshot` 依据；整包重建发现问句、答案、事件时间或边身份改变即拒绝。
2. **独立评分。** 复用现有图内边序列核查，另以快照求有效封闭边；A 题检查路况输出、路线边不穿封闭边、起终点及最短性，B 题检查无路线和解释输出。缺失作答、错误方式、过期事件被误当有效、相邻边被误封、声称成功但未提供边序列均不得计成功。评分器不调用产品规划器或产品核验状态。
3. **小图反例与真实图开发验收。** 先用小图验证生效/过期/其他方式、绕行与真正不可达，再从当前真实校园图重复构建两题并用人工构造的正确/错误投影验证评分。相邻路线、推荐、多轮题必须继续通过，不能为新来源配置改坏已冻结题包。
4. **隔离服务重放门。** 只有本地服务证明连接独立实验数据库，才用 `scenario_live_adapter` 采集真实智能体回放。采集器版本、模型、提示词、工具与数据版本需随运行记录冻结；目前没有这样的运行环境，不能拿生产服务替代。正式 300 题、同底模基线和成本确认依旧是后续门槛。

预期代码边界：新增事件开发题规格与快照、专用来源清单、案例生成器、构包器、离线评分器及对应测试；不修改产品数据库、用户路况或现有冻结来源清单。通过的含义仅是**开发题链路及独立图内判分可重放**，不是模型效果或现场道路验收。

## 本轮完成与剩余门槛

- 已生成 `experiments/datasets/controlled_event_pilot_v1/` 中的两道开发题及独立来源清单。重新运行 `python -m experiments.build_controlled_event_pilot` 会重算来源；冻结文件字节若变化会拒绝覆盖。
- `event_dev_detour_001` 的冻结图内最短绕行约 575.41 米、29 条边；`event_dev_blocked_001` 在当前步行准入图内无路。两题的路况快照均写明 `synthetic_development_only` 和 `campus_truth=false`，不可解释为真实校园管制。
- `python -m experiments.controlled_event_replay --replay <投影结果.jsonl> --run-id <名称>` 是离线判分入口。它重验来源与整包后，按精确路段身份、事件时间及方式验算；必须有与有效快照一致的事件 ID 投影，且成功查询路况的工具调用位于算路调用之前。缺席作答记失败。单独测试中由金标准人工构造的投影可通过，但这**不是模型实际成绩**。
- 隔离服务重放尚未进行。现有 `scenario_live_adapter` 不会投影 `road_events` 和有效事件 ID，也没有把正确的 `no_route` 结果映射为本题需要的 `infeasible` 状态；目前亦未证明它能把模拟事件注入隔离数据库，并在冻结的评测时刻读取。这里的“现在”指模拟快照的 `as_of_epoch`，不是运行机器的当前时间。因此，本轮仅达到离线开发题可复现；不能合并为正式实验结果，更不能把模拟事件部署到生产路况。下一步先完成隔离事件注入、冻结时钟和来自工具结果的路况投影，再做实际智能体重放。

## 2026-10-26 对齐修正

旧版 `controlled_event_pilot_v1` 的绕行事件只在金标准中封闭一条有向边，但产品的路况规则会把该处平行道路一并封闭，共影响 12 条边。因此 v1 只能保留为历史开发记录，不可用于实际 Agent 对照判分。`controlled_event_pilot_v2` 改用另一条边，且以两个有向记录明确表示双向影响；两道题的产品封闭边集合和独立来源解析得到的集合均为相同的两条边。新包有自己的来源哈希，仍是**模拟开发题**。隔离重放具体步骤见 `docs/research/11_隔离路况重放实施计划_20261026.md`。
