# OpenGA 借鉴与「专用 vs 通用」对照核查

核查日期：2026-10-20
输入来源：武汉大学乐鹏教授团队《时空智能体共享服务平台 OpenGA》报告（微信公众号推文，正文以 PPT 截图呈现，经浏览器渲染与图像识别提取要点）。
范围：OpenGA 报告中可迁移的方法论对照珞珈智行（WHU-Walker）的现状，以及本轮据此落地的四项机制增强 + 一条对照基线。
边界：本文记录的是本地代码合同与设计取舍，不代表真实大模型每次调用都正确，也不代表线上或真机已验收；校园现场证据与部分数据属性仍待补齐。

## 一、OpenGA 的核心主张

报告的主张是「时空智能体不只靠通用聊天模型完成，而需要一个面向时空任务的专业智能体框架」，架构为「一个引擎 + 一个平台 + 一套规范 + 三个库」（工具库 / 知识库 / 技能库），并给出：

- **GeoSkill 技能规范**：用标准化模型描述时空能力的结构与边界，让智能体不再「猜工具」；
- **知识注入闭环**：意图理解 → 知识检索 → 规划与反思 → 知识沉淀与自进化；
- **ISO/W3C 溯源模型**：可追溯执行记录、可复现推理链路、步骤与中间结果；
- **GAReflector**：流程控制底座里的规划与反思模块，支持反思与重规划；
- **通用 / 专用智能体对比表**：从核心任务类型、能力接入方式、可信溯源、地理空间适配等维度说明为何需要共享平台。

## 二、可迁移项 → 本项目采纳对照

| OpenGA 精华 | 珞珈智行原有基础 | 本轮采纳方式 | 落地位置 |
|---|---|---|---|
| GeoSkill 标准化能力规范 | 工具 schema 只有自由文本 description | 为注册表内每个工具补结构化能力卡（类别/前置/产出/何时用/何时**别**用/易混淆），并渲染成能力说明表注入 system 上下文 | `agents/tool_skills.py`；`agents/planner.py` 提示词前段注入 |
| 三层知识库 | 只有单层任务卡（领域知识） | 显式分三层：能力知识（工具能力与边界）、领域知识（场景任务卡）、经验知识（成功编排沉淀）；`agents/knowledge.py` 提供三层访问器 | `agents/knowledge.py` |
| 知识沉淀与自进化 | 执行结果不回流 | 运行时把已核验/明确成功的编排追加为样本，离线蒸馏成高置信经验卡；运行时只读 | `agents/experience.py`；`scripts/analysis/build_experience_cards.py` |
| ISO/W3C PROV 溯源 | 工具回调只在内存里，出口分散 | 按「实体—活动—代理」规范化 run 级记录，登记输入指纹、数据/事件版本、产出、核验状态与反思依赖，落盘 + 管理员回放端点 | `agents/provenance.py`；`api/routes.py` |
| GAReflector 规划与反思 | 核验失败后甩一句泛化固定指令 | 先诊断（按核验分组映射到具体冲突类型）再定向重规划，预算受轮次/时间双重约束 | `agents/reflection.py`；`agents/planner.py` |

**明确未采纳**：不改温度（保持 0.0）、不放宽轮次与总时长护栏、不新增工具、不改「核验不通过就不显示路线」的硬规则。这些是既有正确设计，OpenGA 的借鉴不要求放宽它们。

## 三、专用 / 通用对照维度

OpenGA 用对比表论证「为什么需要专用平台」。本项目把它转成可度量的实验对照：新增「通用 LLM 直答（无工具）」基线，与既有规则 / 固定权重 / 最短路径基线并列，回答「专用时空智能体相对通用 LLM 直答多出了什么」。

| 对比维度 | 通用 LLM 直答（基线 B2） | 珞珈智行（专用时空智能体） | 证据来源 |
|---|---|---|---|
| 是否懂地理 | 无路网、无坐标、无地名核验，只能复述常识 | 工具编排 + 路网吸附 + 加权最短路 | `agents/tools.py`、`spatial/routing.py` |
| 可执行性 | 不产出边序列与显示几何，路线类请求不可交付 | 产出精确边序列与 GCJ-02 几何，前端可直接渲染导航 | `experiments/runner.py` 的 `route_executable` 字段 |
| 结果可信度 | 无独立核验，自述即结论 | 独立重算边序列/连通性/预算/约束，返回 pass/fail/unknown | `spatial/result_verifier.py` |
| 可溯源 | 无执行记录 | run 级 PROV 记录可回放 | `agents/provenance.py` |
| 可复现 | 依赖模型生成自由度 | 温度 0.0 + 确定性工具层 + 已核验结果保守复用 | `agents/planner.py`、`agents/execution_dependencies.py` |
| 边界诚实 | 易生成看似合理的校园地点与数字 | 未知项明确标 unknown，不编造校内地名与度量 | `agents/prompts/agent_system.txt`、工具返回值 |
| 可扩展 | 新增能力需重新提示工程 | 注册工具 + 补一张能力卡即可 | `agents/tool_skills.py::validate_skill_coverage` |

## 四、通用基线实测（`queries_v2`，227 个配对）

`experiments/results/generic_v2_results.csv` / `_summary.json` 为本轮用同一模型（`deepseek-chat`，`temperature=0.0`）、**不注册任何工具**跑出的真实结果。它与同数据集上的规则基线并列如下（规则基线为既有产物）：

| 指标 | 通用 LLM 直答（B2） | 规则兜底（B1，既有） | 说明 |
|---|---|---|---|
| 配对数 | 227 | 227 | 含 20 组 / 47 轮多轮对话 |
| task_type 准确率 | 0.8943 | 1.0000 | 通用直答在闲聊/帮助类上分错 |
| 约束 macro-F1（均） | 0.6595 | 0.6436 | 距离维度仅 0.0589：通用模型几乎不识别「最近/最短」 |
| POI F1 | 0.8655 | 0.8954 | 通用直答无别名归一，靠模型自身拼写 |
| 解析失败率 | 0.1013 | 0.1057 | — |
| 权重余弦相似度 | 0.0092 | 0.4235 | 通用直答无法把偏好映射成可计算的权重向量 |
| 路线可执行（`route_executable`） | 0（全 227 条） | — | 无图、无坐标、无核验，路线只能"描述"不能"交付" |

这组数字对本文的论点只提供有限支持，必须按下面的口径解读：

- **它不是能力排行榜**。通用直答在坡度、景观两个约束维度上反而更高（0.9870 / 0.9327），因为这两类表达在自然语言里更明确；专用链路的优势不在"意图分类"，而在**意图之后的计算、核验与可交付性**。
- **差距最清晰的指标是权重余弦相似度和距离约束 F1**：把"快点到/膝盖不好"变成可计算的 `distance/slope/scenery` 权重，是通用 LLM 直答结构上做不到的事。
- **`route_executable` 恒为 0 是定义而非发现**：通用基线没有路网与工具，本就不可能交付可核验路线。它记录的是"缺少什么"，不能当作精度证据。
- 规则基线是既有产物，两边的模型调用时间、配额与运行环境不完全一致；这里只做同数据集的口径并列，不构成严格受控实验。

## 五、可复现的核查方式

```powershell
# 能力卡与工具注册表一致性（覆盖完整、无孤儿、产出取值合法）
python -m pytest tests/test_tool_skills.py -q

# 反思诊断映射与注入指令
python -m pytest tests/test_reflection.py -q

# 溯源记录结构、隐私红线（不含坐标与原始 query）与管理端点鉴权
python -m pytest tests/test_provenance.py -q

# 三层知识拼接与经验沉淀阈值
python -m pytest tests/test_experience.py -q

# 对照基线（需要 DEEPSEEK_API_KEY 与配额；未配置时产出未解析占位结果，不伪造结论）
python experiments/runner.py --method generic \
    --queries experiments/datasets/queries_v2.json \
    --gold    experiments/datasets/gold_intents_v2.json \
    --output  experiments/results/generic_v2_results.csv

# 离线蒸馏经验卡（运行时只读，不在线改写提示词）
python scripts/analysis/build_experience_cards.py
```

## 六、结论与后续边界

本轮把 OpenGA 中「方法论可迁移、且本项目已具备一半基础」的四项补齐了规范，并补了一条对照基线把「专用 vs 通用」的差异变成可度量证据；四项机制都有本地自动化合同与边界测试，但没有一项依赖新算法发明。

通用基线已在 `queries_v2` 上跑出真实数字（见第四节），但它是"口径并列"而非严格受控实验，解读边界已随表列出。

仍需外部条件才能推进的部分不变：经验卡的置信度需要真实流量积累；校园现场通行证据、坡度景观属性与航拍样本仍待人工采集与裁决；Agent 链路自身的工具选择准确率仍需线上真实调用验证（本轮只覆盖本地确定性合同与反思/核验行为）。
