# 面向校园复合出行任务的可追溯时空智能体：引言、方法与实验设置（无结果审阅稿）

> 状态：供师兄和导师审阅研究设计。这里没有正式对照结果，也不声称校园道路已全面实测。正文终稿须依据真实运行记录修改。本稿与 `11_按完成条件推进与证据看板_20261023.md`、`experiments/protocol_v2.json` 配套使用。

## 拟写入引言的主线

校园出行请求往往不止是一次起终点查询。用户可能先表达“想打球”，再补充球类、起点、无台阶要求；也可能在一条既有路线中插入食堂、切换出行方式，或询问突发管制是否影响原路线。此时，模型需要把自然语言中的地点、活动、时间和约束转成可执行的空间查询，并在多轮交互中维持同一个任务。仅评估语言回答是否流畅，无法说明路线是否遵守道路约束，也无法区分地点数据缺失与智能体执行失误。

本研究以武汉大学校园出行为受控场景，研究**显式任务状态和可追溯空间工具执行**是否改善复合任务的完成情况。地点、路网、已确认路况和模型在主对照中固定；比较对象只改变智能体的任务组织与工具执行方式。路线边序列、约束判断和事件时段由独立程序依据冻结数据审查，模糊意图由来源记录和少量独立审查补足。本文的结论范围是所测任务与所用数据版本；图内路径合法不等于实际每段道路均可通行。

拟强调三项可检验贡献，而非预设“效果提升”：

1. 提出带版本的多轮空间任务状态，使地点、顺序、出行方式和硬约束在澄清、修改和重算时可追踪。
2. 将地点检索、路径规划、路况查询和路线反馈组织为留痕工具链；以同一具体边序列检查约束与展示几何。
3. 构建按任务类型分层、带来源和未知状态的评测协议，分开衡量 Agent 执行、受控动态事件与公开影像识别。

## 方法章节建议结构

### 1. 研究对象与输入边界

输入包括用户多轮文本与经明确选择的地图起点、校园 POI 主数据、融合道路图、道路复核层以及管理员确认且有生效时间的事件。POI 和道路的来源、坐标系与版本保存在冻结清单中。高德底图及线上 API 可用于展示或参照，不当作可自由再发布的路网真值。地点到道路的末端接驳、开放时段和现场通行性若缺证据，记为未知。

### 2. 任务状态与工具链

每轮输入抽取任务类型、起终点、途经顺序、活动用途、出行方式、路线偏好和硬约束；缺失的决定性信息以结构化问题澄清。后续回复只修改用户明确改变的字段，保留其余任务条件。工具产生地点候选、路线、路况或天气等结构化结果；候选和路径计算不得由模型自行编造。路况事件带道路边、适用方式和时间范围，由管理员确认后进入规划；过期或撤销后应恢复原有通行状态。

### 3. 独立空间审查

对可自动判定的路线任务，评测器读取冻结图、道路覆写层、复核记录与固定事件时钟，独立检查展示路线的有向边 ID 是否连续、是否存在于图中、是否违反已知通行约束以及是否包含被确认封闭的边。产品自身的核验字段只作诊断，不作为独立评分证据。现实可通行性只在另外取得证据的代表路段上讨论；无证据路段不能算“已验证可走”。

推荐任务的判分不读取题目中预填的“最近地点”名单。评测器依据冻结 POI 用途标签、坐标、路网和事件时钟，重新枚举完整合格候选并计算步行距离。当前末端接驳采用最近图节点与直线估计；涉及明显接驳偏差或第 4/5 名边界不清的题目保留未知或独立审查，不能把图内排序等同于现场到达时间。

## 实验设置（执行前锁定）

| 子实验 | 单位和输入 | 主要结果 | 与主实验的关系 |
|---|---|---|---|
| T1–T5 校园任务 | 路线、地点推荐、澄清、多轮修改、组合任务各 24 个对话；每例三次重复 | 完整任务成功率；状态保持、错误拒绝、硬约束、候选距离、时延和 token 分项 | 论文主实验。120 个编题草稿尚未独立裁决，不能作正式成绩 |
| O1 官方基准 | 固定版本的 BFCL V4 多轮题 ID | 按官方评测器单独输出调用成绩 | 测通用函数调用；不并入校园任务分数 |
| D1 动态事件 | 同一校园边在事件生效和到期后的受控输入 | 正确绕行、到期恢复、任务状态保留 | 检验事件进入空间决策；不代表视觉识别准确率 |
| V1 公开视频模拟 | 公开视频与假设校园边的人工映射，视频为独立单位 | 处理覆盖、候选证据、管理员审核、发布及重算链路 | 证明模拟流程；异地视频不是真实武汉路况 |
| V2 标注图像 | 固定 VisDrone 标注图像选择清单 | 人车检测精确率、召回率、F1 和无法判断比例 | 只衡量公开图像检测；不代表事故、积水或拥堵识别 |

主对照首先固定同一 DeepSeek 模型，比较：（A）珞珈智行完整状态与工具链；（B）只有普通对话历史、可调用相同校园工具的 Agent；（C）DeepSeek Harness 实现且只暴露同一校园工具的 Agent。三者使用同一 POI、图、事件快照和输入顺序；记录真实解析后的模型 ID、工具清单及参数签名、最大模型轮次、单次输出上限、时限、调用量、token 和失败。Harness 默认文件和命令工具必须在对照中关闭；否则条件 C 只可作异构参考，不能用于主效应归因。Kimi、GLM 是跨模型扩展，不替代同模型对照。

完整对话是最小评分单位。每例三次独立重复，先按例汇总成功比例，再计算条件间的配对差；置信区间按预先定义的任务模板族重抽样，避免把同一模板的三种改写误当独立样本。各 T 组只有八个模板族，组内区间可能很宽，应如实报告。未知证据、服务失败和无结果分别列数；不把“未知”暗中计为正确。费用上限、停止规则、评分代码和测试集哈希必须在正式批量运行前固定。

## 样本与裁决程序

开发材料用于修复功能，留出材料只在配置冻结后评分。当前 60 条开发题和 120 条正式候选均属于**已见编题材料**；它们的格式与分层配额已检查，但不是盲测成绩。自动金标准只覆盖可以由冻结图、明确地点 ID 与事件边推导的事实；含歧义、用途边界或真实通行判断的题目保留审查卡，记录审查人、证据和判定。正式测试题若被用于调试，该题及同模板族应退出留出集。

正式评分前检查题目与对照条件的模板族、OD、原始提示、来源视频和来源组重合；检查快照哈希、工具权限、模型版本和代码提交。路线审查与任务语义审查分层输出，避免把地图数据误差错误归因于 Agent。

## 已知局限与待补材料

- **尚无正式主实验结果。** 需要完成金标准、独立留出、三条件真实试跑、费用审查和冻结后才能填入表格。
- 已做少量双条件开发试跑，用于检查工具链与证据格式；没有重复、独立金标准和 Harness 等条件，不能推断完整智能体的优势。
- 当前公开图像上的人车检测为开发阶段的固定验证集结果，不能推断校园人流、事故或积水效果。
- 异地公开视频到校园道路的关系是模拟标签，不能表示视频拍摄时该道路真的拥堵或封闭。
- 路网审查能判断冻结图上的边与约束一致性；现场是否开放、是否临时施工仍需要特定证据。
- 没有真实用户研究时，只能报告脚本化任务执行，不能声称用户体验得到受试者实证改善。

## 师兄/导师审阅重点

1. 主贡献是否聚焦“多轮状态＋可追溯空间工具执行”；视觉部分作为独立扩展是否适合目标专刊。
2. 三条件同模型对照与 T1–T5 分层是否足以回答主问题；是否需要缩减或补充消融。
3. 论文对“图内合法”和“现场可走”的区分是否清楚；哪些代表路段确需额外核查。
4. 若 Harness 无法获得完全相同的工具权限，是否把它降为辅助对照，并以普通工具 Agent 为主要基线。
