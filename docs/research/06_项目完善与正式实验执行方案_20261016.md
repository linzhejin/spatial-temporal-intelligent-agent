## 1. 项目定位和下一阶段目标

项目定位为**面向校园复合出行任务的时空智能体**：把用户表达、当前位置、地点用途、道路和带时效的事件，转化为可执行且可以解释、修改的出行方案。无人机提供观测证据，管理员确认其位置、有效期和影响后，智能体据此调整空间决策。

沿用 Flask、LangGraph、PostgreSQL、NetworkX、Leaflet 与 OSM＋高德＋课程数据的现有架构。论文继续围绕三项机制组织：**情境关联、执行核验、变化更新**。先让三项机制在真实应用中运行，再用公平对照判断是否产生收益。无人机四类能力继续保留在产品任务中，各自独立达标；不能用软件流程完成代替识别效果，也不让缺少某类校园正例阻断 Agent 主实验。

总体研究问题：在相同模型、工具、空间数据与预算下，显式情境关联、执行后核验及变化驱动更新，是否提高复合任务成功率、降低硬约束错误，并在结果正确的前提下降低重复执行成本？

### 正式运行的共同规则

1. **相同输入条件：**智能体组使用相同模型版本、历史、工具权限、POI/路网/事件/天气快照、领域事实、调用预算、超时和重试政策。天气先固定快照做机制实验，真实线上天气另做稳健性检查。知识增强组拥有相同事实，只改变组织/使用机制。
2. **独立任务：**六类场景为地点推荐、模式/通行条件、多途经/行程、复合工具、多轮修改、事件/不可行。每题包含完整消息、模板与 OD 分组、预期 POI ID/顺序、硬判据、可行性依据、允许的澄清、所需输出和复核记录。
3. **评分独立：**不以模型回答“完成”或产品核验 `pass` 作为真值；复核边链和条件。可行任务被拒绝、只完成复合需求的一部分、静默丢约束均算失败。预期澄清则按是否问对、是否保留其他条件评分。
4. **未知的分母：**完整任务成功率以全部任务为分母；硬约束违反率以可判定空间输出为分母，同时报告输出覆盖率、未知和拒绝数。数据未知导致无法完成需要归因，不能悄悄剔除使结果变好。
5. **重复与统计：**每场景拟重复 3 次；按场景配对、按场景簇重采样给出差值与 95% 区间，三次重复不当作三个独立样本。用户研究按人、视觉按航次/事件分组。先指定主指标，其余探索项分开报告；不以“p 小于阈值”替代效应大小和失败分析。
6. **预算：**4 个主条件＋3 个消融 × 300 场景 × 3 次约为 **6,300 次完整场景执行**，每场景含多轮与多次模型调用。先用开发集估计耗时/token，再在正式运行前冻结预算与规模；不得运行到结果满意才停止。第二模型先按预先分层选定的关键子集复核，不默认把所有实验翻倍。
7. **冻结后修复：**运行中发现故障先记录原结果和版本，修复进入开发集。若已查看测试错误并据此改功能，该批测试降为已见样本；主结果需另备未见样本或明确作为修复后复测，不能继续称同一批独立盲测。

建议工程发布目标：开发/验收集中已知硬约束违规、跨任务串扰、过期操作覆盖和重复发布为 0；拟定完整任务成功率目标为至少 95%，正式测试中的实际结果及区间仍全部报告。该目标是产品验收建议，不是期刊录用条件；不能通过拒绝所有任务达成零违规。

## 5. 路网、POI 和偏好属性的有限补齐

- 路线选择约 **9—12 个代表场景**，复用既有 6 组 OD，并覆盖科技门—玉兰二门跨学部连接、澄波门、星湖园食堂、桂操/梅操、台阶和门禁。路线去重后锁定，集中核查影响可达性和结论的连接、入口及异常段。
- 判定保留“有依据可通行、已知不可通行、未知”，记录时间与方式。课程数据、自强大道教学断点说明和用户已确认改正继续保留；高德路线可作参照，不能自动作为现场真值。
- 位置准确性、末端接驳、图上连通性和现场通行性分开报告。不要求逐条实测全校 14,622 条有向边，也不把每个方向的边当独立道路。
- 风景/平坦模式先做“同 OD 是否产生有解释的差异、绕行是否受限、数据不足时是否明确”的验收。只有存在独立参考的样本才报告坡度误差或主观景观偏好效果。
- 成本 v2 与画像学习先保持实验状态。上轮 240 条偏好路线全部降级为距离，无法证明个性化有效；应先解决输入证据和回退行为，再作同快照对照，不能仅为上线新版本放宽门槛。
- OGE 仅作为有来源的可选派生候选；独立审查后再纳入相应实验快照，不能直接覆盖正式标注或把 DEM 推导称为实测。

## 6. 无人机四类能力的落地任务

| 能力 | 接下来的实施和实验 | 达标/边界 |
|---|---|---|
| 人车基础检测与跟踪 | 使用现有检测器与跟踪，标注校园行车/行人区域和目标；比较整图、区域切片在相同计分目标上的漏检/误检与耗时，补小目标、遮挡、移动镜头案例 | 人车分别报告 P/R、计数误差、轨迹问题及无法判断比例；不能用数量直接代表流量或拥堵 |
| 车辆缓行、人流拥挤 | 对持续排队、聚集和移动状态标注事件起止；补停车、红灯短停、普通会车、散行人群的负例；比较整幅统计与区域＋跟踪 | 沿用候选 precision ≥0.90、recall ≥0.80 的预设目标，同时报告样本量和航次区间。低样本达标只说明试点，不外推全校 |
| 机动车事故 | 当前实现已有 AIDER 五分类模型，公开静态图事故 P/R 记录为约 0.929/0.855；下一步获取有许可、独立事件 ID 的视频正负例，做连续事件评估，并采校园正常交通难负例 | 当前启用代码已支持“外部事故事件验证＋校园负例验证”：外部独立测试组至少 3、至少有正例组，校园测试航次至少 3 且误报数为 0，并核对许可、模型/阈值/报告哈希。无需要求你去拍校园事故；这仍不证明校园事故召回率 |
| 道路积水 | 复用现有分割/训练代码，补人工标注的路面与积水范围，单列湖面、阴影、湿路反光负例；按航次分开发/验证/测试，先估计迁移误差再决定训练 | 道路区域积水 IoU 目标 ≥0.60；若报告事件效果，还需独立事件 P/R。已有可见水体伪标签 IoU 0.7752 不能替代人工真值或道路积水结果；没有正例时不算该项验收通过 |

同一影像产生多个候选，逐项保存模型、原片、观察时间、证据片段、区域—路段关联、审核决定和有效期。将“已确认正确事件进入路线”的控制实验，与“从原始影像经过识别/复核进入路线”的全链实验分开，后者保留识别漏报和人工纠错成本。

**第一次航拍：**选 3—5 个代表地点，每段 60—120 秒，以稳定镜头为主，另加少量移动/遮挡片段；至少一段超过 3 分钟用于完整覆盖和续算工程验收。保留原片、拍摄时间、位置、航次 ID 及字幕/飞行记录。第一批主要用于判断目标大小、标注负担和开发；再安排至少 3 个独立测试航次，不从同一视频切片冒充独立航次。校园事故正例不作为采集要求；雨后有自然积水时再补对应样本。

现有入口继续使用：

- `scripts/vision/prepare_campus_water_data.py`：完整解码、按地点/航次拆分和标注准备。
- `scripts/vision/evaluate_campus_detection.py`：`--inference-path compare` 做相同样本整图/区域对照。
- `scripts/vision/evaluate_campus_events.py`、`scripts/vision/evaluate_accident_events.py`：事件层评估。
- `scripts/vision/audit_campus_field_readiness.py`、`vision/model_release.py`：证据与启用核验。

先测一个代表视频的处理时间/视频时长比、队列等待和峰值内存，再确定训练/推理算力。已有 CPU 处理证据属于离线分析，不能预先承诺实时。权重、原片、人工标注及大结果留在既有仓库外实验目录；代码仓库保存协议、清单哈希和复现说明。
