## P1：无逐轮参考的 27 轮分类

来源为 `output/experiments/scenarios_test_v2_diverse_repro_T3T4_20261025.json` 和 `output/experiments/T1_T5_turn_evidence_coverage_sourcechecked_20261025.json`。逐题核对了消息顺序、期望轮次和正式 POI 名称。下表中的“规则”是类别层面的人工裁决或任务语义，**不是 27 题的独立逐题金标准**。

| 家族（每族 3 题） | 缺参考的轮次 | 编题预期 | 已有规则或证据 | 仍缺什么 |
|---|---|---|---|---|
| `T3_ball` | 首轮 | 问球类，保留起点 | 用户裁决卡 1–3 同意 | 三个具体起点的来源及实际交互 |
| `T3_ball_steps` | 首轮 | 问球类，保留避台阶 | 打球须问球类；硬约束不能丢 | 逐题约束保持与地点来源 |
| `T3_ball_bike` | 首轮 | 问球类，保留骑行 | 打球须问球类；出行方式不能丢 | 逐题方式保持与地点来源 |
| `T3_exercise` | 首轮 | 问运动类型，保留起点 | 用户裁决卡 4–6 同意 | 三个具体起点的来源及实际交互 |
| `T3_exercise_near` | 首轮 | 问运动类型，保留“附近”锚点 | 泛运动用途不足以唯一确定设施 | 三处地点是否只作位置锚点的具体裁决 |
| `T3_destination` | 首轮 | 问终点，保留起点和步行 | 消息中只有起点 | 三个起点的来源及实际交互 |
| `T3_destination_flat` | 首轮 | 问终点，保留平坦偏好 | 消息中只有起点和偏好 | 三处餐饮起点的来源及实际交互 |

`T3_destination_weather` 曾被误读为“补起点后还要追问”：实际草稿是两条用户消息和两条期望轮次。第一轮因缺起点追问，第二轮已有起终点并要求 `route + weather`；无需修改生成器。对可见草稿执行结构核对：**27 轮、9 个家族各 3 题**，该家族的第二轮均要求路线加天气，`T4_weather_after` 第二轮均要求天气且保留首轮路线。

以独立测试 PostgreSQL 和固定天气夹具运行两项代表性 API/worker 回放：补起点后保留目的地并返回路线与天气；追问天气后不重新规划已有路线。**2 项通过**，JUnit 为 `output/experiments/p1_weather_state_replay_20261025.xml`，SHA-256 `abe2c477a09cf7bc743958dbdceee35625cbac4cf7feabfc60313c5e24a72521`。回放使用替身 Agent 与固定路线，用于核对持久化任务状态和 API 链路；未覆盖三学部具体题的真实模型回答或路线质量。全表仍保留 27 轮“无独立逐轮参考”的标签，不因类别规则或代表性回归而计入正式判分。
