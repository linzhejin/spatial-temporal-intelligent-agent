# 2026-10-25 T5 三阶段产品开发回放

## 目的与范围

用已见开发题 `v2h_T5_sport_then_food_1` 检查真实 Flask API、持久化任务、worker 和 Agent 的连续交互：从总图附近找篮球场，选球场后找附近正餐，选餐饮点后生成从原起点经球场到餐饮点的全程步行路线。输入来自 `output/experiments/dev_t5_sport_then_food_20261025.json`，已明确标为 development；该题及本轮修改不得再作为未见测试题。隔离数据库为 `whu_agent_experiment_test`，未触碰生产事件。

## 发现与修复

首次回放三轮均停在追问。`ordered_via_request` 将“先去打篮球，再找附近能吃饭的地方”中的活动搜索误当作两个具名途经点，随后地点解析失败。现先区分开放式活动与具名地点，交由用途检索和逐轮选择处理。

第二次回放前两轮已经给出候选，但第三轮失败。用户说“从刚才的起点出发”时，地点解析把“刚才的起点”当成新的 POI 名，覆盖了任务状态中已保存的阶段起点。现将此类指代交还给结构化任务状态；本轮明确报出的真实地点仍可覆盖旧起点。

同一轮的产品输出可以同时含已完成的第一段路线和下一站候选。旧回放投影仅按 `response_kind=route` 记录，错误地把未完成的复合任务当作全程路线。现将待用户选下一站的输出记录为候选，将第一段边序列单独保留为 `partial_route_edge_ids`，直到最后一轮才记录全程边序列。候选距离顺序由独立候选参考审计，评分器不再要求候选卡片展示路线策略。
