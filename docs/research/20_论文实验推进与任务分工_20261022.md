## 二 校园任务集与样本分组

主实验暂定 120 个完整任务，按下表五组各 24 个组织。每组先设计 8 个不同场景族，每族生成 3 个位置或表达变体，共 40 个场景族。一个完整任务包含从首次需求到最终交付的全部对话轮次；多轮对话不能拆成互不相关的单句计数。

| 分组 | 任务内容与示例 | 主要变化 | 关键检查 |
| --- | --- | --- | --- |
| T1 明确通行 24 个 | 从星湖园食堂到卓尔体育馆，避开台阶 | 三学部起终点、距离、出行方式和硬约束 | 地点解析、路线连通、约束满足 |
| T2 用途推荐 24 个 | 我在信息学部，想找最近的食堂 | 起点、餐饮、篮球、学习和生活服务用途 | 完整候选集、用途正确、位置排序 |
| T3 必要澄清 24 个 | 我想打球 → 篮球 → 从桂操出发 | 缺球类、缺起点、地点歧义、其他选项 | 问到缺失项、可靠别名不重复确认 |
| T4 多轮修改 24 个 | 先去食堂再去体育馆 → 换骑行 → 终点改为图书馆 | 连续改地点、方式、途经点及局部条件 | 保留未修改项、执行新条件、无旧任务污染 |
| T5 组合与异常 24 个 | 先查天气，再顺路吃饭去图书馆；另含不可达和工具超时 | 多子任务、拒绝、服务错误和证据不足 | 子任务不丢失、明确失败、可恢复 |

**起终点变化是一个样本维度，不是整套实验。**三学部均覆盖近距离与跨学部路线，含校门连接、小路、台阶、不同位置的同类设施。起终点名称只是示例，正式生成时使用冻结 POI ID 与图内可核对的路段，不凭名称假定路线可达。

每条记录至少保留：任务 ID、来源、场景族、起终点组、原始消息、每轮预期状态、起终点与有序途经点、用途、出行方式、硬约束、允许的未知项、路网与事件快照、判分依据。示例“改成骑行”应触发重新检查骑行可通行性，不能照搬步行路线。

120 是控制工作量的起步设计，不是已完成数量或统计充分性的保证。沿用已有开发集排错；另建主测试集，按场景族和起终点组隔离，公开相似模板与共享道路范围。预实验后根据波动、区间宽度和调用成本确定最终规模，冻结后不得为追求好看结果随意扩样。

## 三 官方样本与影像样本的使用

| 数据组 | 起步范围 | 用途与结果边界 |
| --- | --- | --- |
| O1 官方工具调用样本 | BFCL 多轮样本 40 个，拟按基础多轮、缺参数、缺函数、长上下文各抽 10 个 | 评估通用工具调用与澄清；保留官方题目、环境、评分器和样本 ID，单列结果 [1] |
| D1 动态事件样本 | 24 个任务，6 类事件各 4 个 | 测封闭、方式差异、缓行策略、时间窗口、撤销和无关事件等情境 |
| V1 公开影像模拟联动 | 6 组独立公开视频片段，每组匹配 2 个地图场景，共 12 个联动案例 | 测影像分析、复核、模拟位置绑定和 Agent 响应；独立影像组数仍为 6 |
| V2 公开检测子集 | 优先取已有 VisDrone 官方带标注划分；首轮固定 100 张分层样本 | 核查人车框与计数，不把检测结果等同于拥堵真值 [2] |

**“官方样本”分两种。**BFCL 等研究数据集提供正式评测题和检查逻辑；模型厂商文档中的工具调用示例只用于接口接通检查，不计入论文主结果。官方样本也可能被模型预训练接触，不能称为保证未见的盲测数据。若改写为武大地点和校园工具，必须另标“改编任务”，不能沿用官方分数或与其排行榜直接比较。

O1 保持官方执行环境，对各配置提供相同的官方工具。珞珈智行若尚未支持非校园任务状态，先用于三个模型的标准工具调用能力参考；架构排名只在全部配置均适配的任务上进行，不能把不适配或未运行当成零分。T、O、D、V 四类结果分别报告，不平均成一个总分。

**优先复用本机数据。**已确认 D 盘存在 VisDrone DET val/test-dev 压缩包及 Songdo Traffic 的视频、参考帧、分区和轨迹压缩包。这里只核对到文件存在，执行阶段仍须检查哈希、解压和可解码性。Songdo Traffic 的公开视频适合车流片段，VisDrone 图像可用于人车检测；若需连续行人分析，再补其视频划分 [2][3]。

单图只能支持画面检测或提示，不能独立判断持续拥堵。公开视频若没有拥堵标签，就将输出作为待复核候选；有参考轨迹也须先核对时间对齐，不把邻近时段轨迹当作视频真值。当前只做流程不需要训练，已经用于调参的验证集与正式留出集分别记录。

## 四 模型与智能体架构对照

模型负责理解和生成，Harness 或 Agent 框架负责记忆、调工具和控制执行。两层分别比较，才能判断改进来自哪里。DeepSeek Harness 官方项目已核实存在，并提供 Kimi、GLM 等模型接入说明；其仍在快速迭代，实验须固定提交版本 [4][5]。

| 架构配置 | DeepSeek 模型 | Kimi 模型 | GLM 模型 |
| --- | --- | --- | --- |
| A0 普通工具 Agent | 必做 | 必做 | 必做 |
| A1 DeepSeek Harness | 必做 | 必做 | 必做 |
| A2 珞珈智行完整架构 | 必做 | 必做 | 必做 |

A0 使用标准“模型请求工具—执行—返回结果”循环，保留正常聊天历史与错误处理。A1 保留 Harness 自身的通用会话、工具和恢复机制，通过薄适配层接入同一校园工具；不能偷偷调用珞珈智行的完整规划接口代替其自身编排。A2 使用现有任务状态、用途检索、能力说明、结果核验和受限重规划。记录各机制开关与默认值，避免故意削弱基线。

另在预先选定的同一模型上运行两个消融：A2 去掉结构化任务记忆但保留聊天历史；A2 去掉额外结果核验及其重规划触发，但保留相同工具。消融结果揭示机制贡献，A2 与 A1 的整体差异只支持整套架构的效果，不能据此把收益单独归给某一组件。经验卡只允许来自开发集，正式实验期间固定为只读。

模型按 DeepSeek、Kimi、GLM 三个系列各选一个具备工具调用能力且可用的版本。执行前登记完整模型 ID、提供方、API 地址或权重版本、推理设置、上下文上限与访问日期。API 能访问不等于模型开源；若使用开放权重模型的托管接口，应如实写明，不能宣称本地复现了权重。

先用 10 个开发任务核对九种组合的工具协议与会话兼容性，再冻结配置。只有凭证或额度确实缺失时才集中向负责人提出一次需求。某个模型或组合不可用时记录未运行和原因，不以另一模型的结果补位。首轮先跑 DeepSeek 三架构，再补 Kimi、GLM，完整矩阵完成后再形成跨模型结论。

## 五 公平条件与评分规则

各架构获得相同的 POI、道路、路况、天气快照、工具接口说明和用户输入；提示词可以体现各自架构，但不得额外提供答案或隐藏地点事实。每个任务清空跨任务状态，保留本任务正常历史；相同模型采用相同推理档位和输入限制。调用次数、输出 token、单轮时间、总时间及重试预算在开发阶段锁定并随结果公开。

| 指标 | 分母与判定 |
| --- | --- |
| 完整任务成功率 主要指标 | 每个任务先计算重复运行成功比例，再等权汇总；所有计划运行均保留，缺失或超时不剔除 |
| 约束保持与违反 | 在确有约束的任务上核对原始用户条件；分别报约束丢失、违规路线和无结果比例 |
| 推荐与澄清正确性 | 在相应任务子集核对用途、距离排序、缺失槽位；并列合理候选及等价操作允许通过 |
| 动态事件处理 | 检查事件路段、方式、时间、撤销和重算；正确判定不可达可通过，误称畅通不可通过 |
| 运行开销 | 各组报告首个有效反馈与最终结果的 P50/P95、模型及工具次数、token 和实际费用 |
| 证据与未知情况 | 单列未知、缺真值、解析失败、错误重试、异常退出；不将未知当成成功 |

路线由独立评分代码读取冻结图、事件和边序列，检查连通性、方式、途经顺序与硬约束；推荐距离与完整合格候选集计算结果对照。不得直接把产品的“核验通过”字段或生成的解释当作评分答案。图内核对通过只能支持图内正确性，现场可通行性另列。

开发阶段暂按每个主测试任务重复 3 次规划；温度为零也记录实际波动，不声称必然确定。主矩阵运行量约为 120 × 3 架构 × 3 模型 × 3 次＝3,240 次任务执行；两个单模型消融另需 720 次。正式调用前根据开发阶段 token 和时长估算预算，费用上限不足时先公开缩减方案再冻结，不能静默删去失败组。

同一题的重复运行、同一场景族的变体、同一视频的多次地图映射均有关联。主分析使用按场景族配对的差值与 95% 聚类 bootstrap 区间；影像按原视频组汇总。先报告效应大小、分母和区间，必要的多重比较采用 Holm 校正。样本少或区间宽时明确不确定，不把“没有显著差异”解释为两方法等价。

## 六 无人机影像模拟联动流程

首版流程为：公开影像导入 → 圈定画面观察区域 → 生成人车分析结果 → 形成候选 → 管理员复核 → 绑定模拟道路与有效期 → Agent 查询、解释和调整路线。实地航拍在此后补充，不阻塞主实验。事故和积水保持独立扩展，不作为这轮简易流程的必达能力。

1. **准备样本。**从公开影像选取正常通行、车辆较密、停车、短暂停车及画面不稳等片段；先检查完整分析范围、模型版本和失败状态。一个视频的前后帧不拆到开发与测试两边。
2. **模拟位置。**从冻结校园路网的合格路段集合中，按三学部、道路用途和是否存在替代路径分层随机抽取，固定种子 20261023。随机的是用于实验的道路关联，不是影像的真实拍摄地点；不得在地图矩形里任意撒点后吸附到邻路。
3. **关联区域。**保存画面区域 ID 与目标 edge_id 的对应关系，同一物理道路的方向边明确列出。地图定位标记仅作查看入口，事件必须关联可核对的道路边，不能靠一次最近点吸附自动扩大影响范围。
4. **登记来源。**原始公开来源、原拍摄时间和地点保持不变；另设模拟地点、实验时钟和地图快照。界面、事件记录与论文图注均显示“公开数据模拟位置”，不以刚上传的时间冒充当前观测。
5. **复核候选。**检测数量与轨迹作为证据，管理员可确认、排除、修改路段和有效期。没有候选也保留已分析范围与原因，不强行制造阳性结果；判断不足可记录提示或未知。
6. **输入 Agent。**将已确认的结构化事件通过路况工具提供给所有对照架构，附事件 ID、类型、路段、适用方式、时间、来源和证据摘要。默认传结构化结果，避免因某个语言模型不支持图像造成不公平比较。
7. **观察恢复。**固定同一组起终点，检查事件确认前、确认后、到期或撤销后的查询与路线。重算须保留途经点、偏好和对话任务；选路解释须引用实际生效的事件。

所有模拟操作只进入实验数据库和实验事件命名空间，测试当前时间由固定实验时钟控制。线上用户路况查询必须排除模拟记录；这项隔离未实现和验证前，只能离线回放，不能把公开影像挂到生产地图上发布。

建议新增的记录字段为 source_dataset、source_item_id、media_sha256、source_capture_time、simulation_location、simulation_clock、roi_id、edge_ids、graph_hash、analysis_interval、model_hash、review_status、valid_from、valid_until、affected_modes、action 和 evidence_ref。它们是实施要求，并非本次已上线接口。

## 七 动态事件与视觉实验的判定

D1 的 24 个任务按六组各 4 个设计：路段封闭、仅影响特定方式、缓行与路线策略、生效与到期、撤销恢复、无关事件与无替代路径。每组包括不同起终点或不同道路连接。受控路况由实验脚本按预登记规则注入，无需在校园制造封路。

“最短路径”继续按可通行道路的纯距离求解；缓行影响时间估算和提示，避开拥堵或综合策略再使用对应通行成本。未知路况应答为暂无覆盖信息。当前路线与事件不相交时，不应无故改变目的地；确实无路可走时，明确不可达优于放松硬约束。

视觉部分分开记录三种输入，防止流程实验变成自我证明：真实模型输出用于端到端案例；公开真值或有证据的人工复核结果用于条件化的下游决策检查；人为构造的事件只用于接口、时效和错误处理测试。后两者不能记作模型识别成功。

| 检查层 | 本轮验收方式 | 可以报告的内容 |
| --- | --- | --- |
| 检测与视频处理 | 标注子集核对检测；对视频核对总时长和实际分析范围 | 公开子集检测结果、处理覆盖率与耗时 |
| 候选与复核 | 正常、停车、短停和证据不足均有案例，逐项记录决定 | 候选及复核结果；无事件真值时只做案例描述 |
| 位置与事件 | 模拟标记、边 ID、方式、实验时钟、有效期一致 | 模拟道路关联正确性与事件生命周期结果 |
| Agent 响应 | 同一事件输入比较三架构，并核对无损重算 | 已给定事件条件下的决策正确性 |
| 端到端 | 从实际模型输出到最终路线保留完整记录 | 公开影像与模拟地图的联动能力及失败原因 |

V1 先用 6 组独立视频完成 12 个映射案例，全部说明选取标准和复用关系，不用于宣称拥堵精度已达 90%。如果公开样本没有目标事件正例，记录该能力尚无法评估；不能删掉普通通行样本来提高准确率，也不能把“车辆多”自动标成拥堵。

结果表预设为：实验组、模型、架构、独立任务或视频组数、重复次数、成功与失败数、主指标及区间、时延、费用、主要错误。本轮文件不填入未运行的结果。T1—T5、O1、D1、V1/V2 分表，图内正确、公开视觉表现、模拟联动和校园现场证据分别标注。

**先解决旧评测协议的冲突。**当前 protocol_v1 及评分代码固定要求 300 个测试场景、每题独立人工裁决和明确工具序列，与本方案的低人工方案不一致。P1 必须新增有版本号的协议，区分官方真值、独立程序参照、人工抽审和未知四类来源；同步修改评分与拆分检查。保留旧协议和旧结果，不伪造 manual_independent 标记，也不能关闭校验后将草稿称为正式测试。

新评分以任务终态和约束为主，工具序列仅作诊断，允许不同但合理的调用路径。需要修改 experiments/scenario_evaluator.py、scenario_split_audit.py、scenario_runner.py 及相关协议适配；现有 live adapter 仅采集开发场景，还需补正式采集和基线适配，不能直接声称已可跑全套对照。

**负责人必须配合的只有三类事项。**一次审查约 12—20 张真正有歧义的任务卡；一次抽看约 6—10 个模拟关联和复核片段；在两个审阅节点把稿件给导师或师兄并反馈意见。预计合计约 60—90 分钟，不含沟通等待；若没有模型凭证或额度，集中处理一次。规则可判的条目由程序核对，不安排全量逐题、逐路或逐帧人工标注。

后续借到无人机再选 2—3 处代表位置短拍，作为真实接入案例；这是增强证据，不是前述主实验的启动门槛。真实用户研究若不开展，就不写“已证明用户满意度提升”。

## 九 论文结构与提前审阅安排

暂定题目为“面向动态校园出行的任务状态保持与事件驱动时空智能体方法”。可沿用现有论文作为底稿，重点重写研究问题、实验设计和证据对应关系。题目与创新点最终随结果调整，不提前写成架构必然优于所有通用智能体。

| 章节 | 要回答的问题 | 对应材料 |
| --- | --- | --- |
| 引言与相关工作 | 模糊、多轮、动态需求为何给空间决策带来困难；已有方法缺什么 | 代表文献、项目失败类型、三个明确研究问题 |
| 问题定义与方法 | 如何表示任务、执行工具、核对空间结果并利用事件 | 任务状态、工具合同、边序列核验、复核事件与有界重规划 |
| 数据与实验设置 | 样本从哪来，比较谁，怎样保证公平 | T/O/D/V 样本表、九配置矩阵、拆分与判分协议 |
| 结果与分析 | 哪些任务改进、哪些无收益，机制为何有效或失效 | 主对照、记忆与核验消融、耗时费用和失败案例 |
| 影像联动与讨论 | 观测如何进入空间决策，模拟能证明什么 | 公开影像、模拟道路、事件时间线和案例边界 |
| 结论 | 哪些主张已有证据，哪些仍待现场验证 | 与实验一一对应的结论和限制 |

引言按四段展开：先描述校园出行中的复合需求；再讨论通用工具 Agent 对任务状态与空间约束的一致性挑战；随后提出本文方法及可验证假设；最后列出实验范围。相关工作区分通用 Agent 框架、地理空间智能体和动态观测决策，不能只罗列模型名或软件名称。

方法图突出“用户需求与状态—工具执行—空间结果检查—反馈修正”的主流程，并将“影像候选—管理员复核—带时效事件”接入共享路况。借鉴的现有机制如实引用；不能将使用 LangGraph、ByteTrack 或调用 API 本身写成新算法。

**第一轮先给师兄看架构和引言。**建议在 10 月 27 日前准备题目、研究问题、引言、方法图和实验设计表，即使结果尚未完成也可以审查研究范围。**第二轮再给完整稿。**正式实验后补齐结果、局限和复现附件，再于 11 月中旬提交审阅。只有完整稿达到要求才称“投稿稿”，当前含待补实验的 Word 不称为成熟论文。

图表建议控制在：系统方法图、样本与对照设置表、任务成功及约束保持图、消融与成本表、事件时间线和视觉联动案例图。风景、平坦偏好的属性仍有证据缺口，主实验优先研究可核对的用途、距离、通行和台阶等约束；若使用人工构造坡度或景观值，必须单列模拟属性实验。
