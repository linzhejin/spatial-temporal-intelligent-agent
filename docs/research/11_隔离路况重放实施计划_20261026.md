# Isolated Simulated Road Event Replay Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Obtain actual local Agent observations for two simulated road-event development tasks without writing production state, and score them against independently frozen graph answers.

**Architecture:** Keep event fixtures and results under the experimental dataset and run directories. A local-only readiness gate must prove both PostgreSQL and road-condition JSON isolation and a frozen event time before any Agent call. Project event IDs only from a successful `list_road_conditions` tool result; the independent scorer must never infer them from the fixture or the model's prose.

**Tech Stack:** Python, Flask, PostgreSQL, NetworkX, pytest, existing JSON road-condition store and Agent tool trace.

## Global Constraints

- `scope=synthetic_development_only`, `campus_truth=false`; no synthetic event goes to the deployed road-condition store.
- Preserve the existing frozen event pilot v1 and all unrelated untracked work. A corrected event packet receives a new version and source digest.
- Keep the current shortest-path policy and product route behavior unchanged. The experiment records disagreement rather than altering product routing to fit gold.
- A graph route proves only frozen-graph feasibility, not campus passability. Formal 300-task/model comparisons stay separate.
- If no isolated database or model service is available, finish code and local integration checks, then record the missing live gate explicitly.
