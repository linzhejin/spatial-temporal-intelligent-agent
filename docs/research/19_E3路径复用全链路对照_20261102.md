# E3 路径复用与完整重算对照

本轮检验已有的最短路维护机制：在什么变化下可以保留原边序列，何时必须重新搜索，以及减少搜索是否降低完整更新流程的开销。范围由2026年11月2日用户确认，不扩展为推荐、活动顺序、路线和自然语言答复之间的通用依赖维护。

## 1. 对照设计

完整重算和保守复用都调用实际产品 API，使用相同任务、路网、事件、时钟和天气。前者仅从已取得的路线状态中移除可选证明句柄，后者携带服务器签发的句柄。两者均实际执行计算、核验和结果生成；评分器不替任一策略生成结果。

六组已见校园起终点各设21类变化，共126个固定条件。每条件、每策略重复3次，计756次更新流程；另为每条件、每策略执行1次操作数探针，共252次。探针会包装搜索权重回调，其耗时不进入计时结果。策略先后顺序在每次配对中以固定种子随机排列，条件按固定清单执行。

| 条件组 | 具体变化 | 检查重点 |
|---|---|---|
| 可以保留旧边序列的情形 | 无变化、路外新增封闭、未来事件、已过期事件、其他方式事件、提示事件、受阻后恢复 | 实际不再搜索，同时按当前环境更新估时、事件说明和核验 |
| 道路状态改变 | 路内新增封闭、道路恢复、自然到期、撤销、路内缓行、路外缓行、封闭与缓行组合 | 应重算时实际执行重算，结果符合当前有效图 |
| 任务及环境共同改变 | 方式修改、起点修改、终点修改、硬约束修改、方式与事件联合变化 | 使用当前任务条件，正确交付路线或不可达结果 |
| 版本与可达性 | 基础图路外成本下降、不可达 | 拒绝过时图版本；独立确认不可达，不能以旧路线替代 |

起点、终点和硬约束修改通过新建路线接口执行，是重新发起任务的对照；旧证明与任务修订的绑定由数据库集成回归另行检查。受阻后恢复使用的是受阻前保存的可达路线证明，中间404不会成为可复用结果。

另设三个可手工复算的小图反例：道路恢复、路外成本下降和偏好权重变化。两种产品策略各重复3次，计18次计时执行及6次操作探针。仅监听旧路径的弱策略依据同一实际初始边序列作离线诊断，用于展示漏判条件，不与产品 API 比较耗时。

## 2. 独立评分与统计口径

评分不读取产品 `route_verification` 的结论。它从冻结空间输入重建有效边集合，检查实际返回的有向边序列、端点、方式与硬约束，另算物理距离、最优代价、估时和结构化事件说明。道路关联、静态方式过滤和端点吸附是两侧共同输入，本专项评价它们确定后的维护行为。

正确性分为三种可直接核对的结果：

- 返回路线：边链合法、任务条件满足、代价最优、估时和事件说明与当前路线一致。
- 返回不可达：独立有效图中确实不存在符合条件的路径。
- 图版本改变：先以409拒绝旧状态，再按新版本重建路线。两次 HTTP 请求构成一次更新流程，总耗时包括两次请求。

计时覆盖实际 loopback HTTP 请求、身份和证明处理、路径计算或复用、核验、说明生成及响应序列化。共同初始建路和事后独立评分不计入更新时延。天气固定为空，不调用语言模型。

报告给出逐次记录、同条件配对差、变化类型汇总和六组起终点分别汇总。三次重复用于描述重复运行波动，不作为三个独立场景；六组起终点是已见固定子集，不作未见任务总体的显著性推断。

操作数包括实际 `nx.dijkstra_path` 调用，以及独立探针测得的每次搜索邻接展开次数。后者指发生权重回调的不同源节点数；每次搜索内去重，跨搜索相加。目标提前终止、无出边节点不计，自有预算标签搜索不在该指标范围内。

阶段耗时互相包含，不能相加。`verification` 字段仅表示工具路由核验封装的调用和耗时，新建路线接口的直接核验包含在总请求耗时中，但未单独归入该字段。

## 3. 运行与结果

六组校园起终点、21类变化的126个固定条件已完成。纳入主分析的756次计时更新与252次操作探针均通过独立评分；无缺失键、重复键、复用判定错误或跨重复／探针语义不一致。两策略各有357次路线交付和21次正确不可达；18次图版本拒绝后重建属于各策略357次路线交付的子集。

| 结果与开销 | 完整重算 | 保守路径维护 |
|---|---:|---:|
| 计时更新流程 | 378 | 378 |
| 独立评分符合预期 | 378 | 378 |
| 实际复用旧边序列 | 0 | 126 |
| Dijkstra调用数（计时批） | 360 | 234 |
| 完整更新时延中位数／秒 | 4.372 | 5.085 |
| 完整更新时延P95／秒 | 36.319 | 40.913 |
| 独立操作探针数 | 126 | 126 |
| 邻接展开次数（探针批） | 174379 | 108364 |

378组计时配对的结果类型一致，其中357组返回路线且最优代价一致；21组不可达不进入代价比较分母。搜索调用由360次减少到234次，减少35%。但在实际复用的126组配对中，维护减去完整重算的时延差中位数为+0.961秒，时延比中位数为1.214。当前实现证明了受限复用条件下的结果有效性和搜索量减少，尚未取得完整更新时延收益。阶段时延用于进一步定位开销，不能由这些数据直接认定某个阶段造成全部差异。

三个受控反例完成18次计时与6次探针，独立评分全部通过。仅监听旧路径的离线弱策略在三类变化下保留了仍可行但不再最优的路径：道路恢复为220米对200米，路外成本下降为200米对160米，偏好变化为加权代价1.78909对1.24。其作用是说明更新判断的必要条件，不能当作第三种实际API策略的效率对照。

### 中断与续跑

2026年11月2日22:35:49，Windows记录电脑合盖进入待机，打断了第六组“其他方式事件”的一次操作探针。母段最后一条计时记录于22:35:43写入；已完成的684次计时与226次探针保留原样。中断尝试未取得响应，记录为基础设施中断，不记为成功。

续跑前固定了缺失键和合并规则：保留母段910条，只补入72次计时及26次探针。尾部13个条件按原随机序列前进452次shuffle后续跑，新建初始路线和证明。两段实际保存762次计时与252次探针，共1014条；额外6次重复计时单独归档，不替换原值。最终分析仍为756次计时与252次探针。新进程和主机状态存在批段差异，两策略保持同段成对；报告采用配对差与六组起终点描述统计，不作独立样本显著性推断。

### 评分输入诊断

最初接口冒烟检查纠正了坐标端点采用WGS84，以及版本字段位于路线状态和证据中的读取约定。校园第一批在第二组“不走台阶”条件下发现参照距离偏短：有效图构造遗漏GraphML字符串数组中的台阶标签，参照路径穿过3条台阶边。修正后，独立最短距离由1310.511188944307米变为1435.056439079222米，与原始产品响应一致；该条件8条原响应重新评分通过。原批328条执行、原评分、停止原因和源码快照全部保留，不进入最终统计。

重新冻结后，126个条件的独立有效边集合与产品方式、硬约束和事件规则逐项核对一致；最终完整实际执行按新冻结版本重新完成。
