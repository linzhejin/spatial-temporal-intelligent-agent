## 候选论文定位

**暂定题目：** 面向校园复合出行任务的可追溯时空智能体：多轮状态与动态空间约束评测。

**候选主问题 RQ：** 在校园空间信息不完备、通行条件可变的多轮复合出行任务中，显式任务状态管理与可追溯空间工具编排，相对使用**同一份地点、路网和路况数据**的基线，能否提高任务完成率、时空约束满足率，并减少状态串扰？

**研究边界：** 主贡献聚焦“用户任务从自然语言到可执行、可追溯空间服务”的状态保持、工具选择、动态约束与失败归因。OSM 与课程道路融合图是共同实验环境；关键路线核查用于防止测试场景建立在明显错误的道路上，不要求学生逐条实测全校道路，也不以取得校方全量开放路网为前提。视觉识别和真人用户实验可作为独立扩展；没有合适数据与结果时不写成已验证的主贡献。最终主问题和创新点仍需导师确认。

## 关键路线的有限核查范围

1. 先使用 `data/route_reference_samples.json` 中已列出的六组 OD；再加入玉兰二门跨学部连接、科技门小路、水生所澄波门连接。台阶、建筑相交、封闭道路或校门疑点优先嵌入这些路线；仍未覆盖的高风险类型再补少量反例。路线数量由预实验去重后锁定，暂以约 9–12 个不同场景安排工作，**不是统计意义上的全校随机抽样**。
2. 每个场景保存代码和图版本、起终点与关键边 ID、出行方式、限制条件、路线截图、证据来源与日期。人工只核查会改变可达性或结论的关键连接、禁行/台阶、门禁与异常穿楼疑点；不要求逐条记录全校数千条道路。用户截图、课程数据和地图商路线可以指示核查位置，但均不自动等于现场通行真值。
3. 每个关键段裁决为 `verified_passable`、`verified_blocked` 或 `unknown`，记录依据与适用时间/方式。已确认禁行仍被推荐是失败；未知不能算成已验证可走，也不能直接算错。对缺证据的场景报告未判定数，必要时缩小现实通行性主张。
4. 正式实验前锁定样本和指标；开发阶段发现的问题另列为修复集，不把修过的例子再当独立留出成绩。所有方法对照使用同一地点、路网和事件快照，避免把数据改进误记为 Agent 改进。

## 公开图像数据的适用范围

- [DroneCrowd（CVPR 2021）](https://openaccess.thecvf.com/content/CVPR2021/html/Wen_Detection_Tracking_and_Counting_Meets_Drones_in_Crowds_A_Benchmark_CVPR_2021_paper.html)：论文报告 112 段无人机视频、33,600 帧，含人群定位/轨迹标注，适合先做俯视人群密度或跟踪验证；它本身不等于校园道路拥堵真值。
- [UAVDT（ECCV 2018）](https://openaccess.thecvf.com/content_ECCV_2018/papers/Dawei_Du_The_Unmanned_Aerial_ECCV_2018_paper.pdf)：车辆检测与跟踪基准，约 80,000 帧；可支持车辆检测/跟踪起步，但普通车辆框不自动构成拥堵或事故标签。
- [CrashVista 项目记录](https://ricerca.uniba.it/handle/11586/598540)：机构页面介绍了约 1,000 张航空/高位事故图像的候选数据集。需在实际采用前核实下载内容、许可、标签与复现条件；当前只列为候选，不视作已获得或已审计的数据。

这些数据可让视觉子系统先开始训练与离线评测，**不能单独证明武大场景的迁移效果**。公开影像通常没有本项目需要的校园路段坐标；因此公开集能检验视觉分类/检测，事件到武汉大学路段的定位与在线管理闭环仍需用武大场景的人工标注或管理员回放样本单独验收。当前不把任何公开集预先说成事故识别充分数据。

## 边完善项目边做实验的迭代节奏

每个小版本都按同一顺序留下证据：

1. **冻结比较对象：** 记录代码 SHA、数据指纹、模型/参数、任务集和系统版本；先保存当前基线输出。
2. **先写该轮假设和测试：** 明确此次要修的失败类型、主指标、对照项、测试样本和硬约束；修完再加样本，不回头改成功口径。
3. **实现一个可验收增量：** 优先修复状态串扰、工具选择、任务恢复与约束执行；关键连接发现明确缺口时再补路网。影像模型作为独立扩展记录，不与 Agent 主效应混算。
4. **复跑同一测试并保留反例：** 记录通过、失败、未判定及原因；路线反例需保留边 ID 和证据，影像反例需保留数据集 split 和预测阈值，对话反例需保留脱敏脚本。
5. **更新矩阵和风险：** 只有真实通过预设门槛才更新“已验证”；“代码已实现”“自动结构校验通过”“地图商线路一致”都不是现场验证。
6. **最后锁定论文版本：** C1 多轮任务与 C2 入样空间场景的证据、数据版本和对照方法就绪后，即可冻结主实验；不等待全校地点与路段逐项核查或视觉模型上线。用独立留出集重跑正式实验，结论只覆盖实际测量范围。

建议的工程顺序：先冻结同一份图、POI 与路况输入，建立 C1 多轮对话主实验和消融基线；并行核查 C2 入样关键路线，发现缺口就修复并重新冻结；随后测试管理员审核后的受控动态事件。公开影像离线实验与真人用户研究分别开展，不作为 Agent 主实验的开工条件。这个顺序不要求遍历全校数千路段。

## 预实验与停止条件

- **先冻结基线：** 2026-10-03 工作代码为 `afe3545`，尚非正式实验冻结版本。正式比较前记录代码 SHA、GraphML 指纹、POI、事件快照、提示词、参数和任务集；基线与完整系统使用相同空间数据。
- **路线试测：** 从现有六组 OD 出发，加入玉兰二门、科技门、澄波门及已知台阶/建筑疑点，预先锁定并去重。核查入样路径的关键通道、限制条件和异常段；无法核实者标为 `unknown`，必要时剔出可通行率分母并报告剔除数。试测样本用于发现缺口，正式留出样本不用于调参。
- **视觉试测：** 固定一个人群数据集和一个车辆/事故候选数据集，先检查许可、标注和按视频拆分；模型在验证集选阈值，留出测试集只评一次。公共集没有事故标签的任务不报告事故检测成绩。
- **主张边界：** 全量数据审计仍保留未知、候选和风险项，但不把逐条实测作为论文主线门槛。若入样关键路线本身无法获得足够证据，则删去对应的“路线现实可通行”结论，保留可验证的状态保持、工具执行和受控约束结果；不能把高德路线一致率或缺证据边当作真值。视觉功能仍可按项目目标开发，但不拿不匹配的公开数据为校园事故识别背书。
- **工具门槛解释：** 当前 `check_agent_research_readiness.py` 将全量校园数据审计绑定到研究快照，属于过宽的软件门槛；在独立的 Agent 主实验就绪评估改好前，不能用其 `ready=false` 推断主实验无法开展，也不能把人工写下的版本号冒充已生成的研究快照。
- **伦理/权限：** 任何真实用户研究、航拍图像采集、可识别人员影像处理和校方路权判断，先按导师与学校要求办理；模型候选不得未经管理员确认进入正式管制。
